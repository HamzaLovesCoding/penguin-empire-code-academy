1 Motors

motorJava
import com.revrobotics.spark.SparkMax;
import com.revrobotics.spark.SparkLowLevel.MotorType;

SparkMax motor = new SparkMax(2, MotorType.kBrushless);   // CAN ID, motor type

motor.set(0.7);      // percent output, -1.0 to 1.0
motor.set(0);        // stop
double asked = motor.get();   // what you COMMANDED. not a measurement
The 80 percent rule

This team fried a motor at around 90 percent output; afterwards it would only run for about five seconds. Stay under 0.8, or add a second motor. Put the clamp inside the subsystem so no caller can bypass it.

the clamp
double safe = Math.max(-0.8, Math.min(0.8, speed));

2 Encoders

encoderJava
double pos = motor.getEncoder().getPosition();   // rotations of the MOTOR shaft
double vel = motor.getEncoder().getVelocity();   // RPM

motor.getEncoder().setPosition(0.0);             // "call this spot zero"
CallUnitMeans
getPosition()RotationsMotor shaft travel from the last zero. Signed
getVelocity()RPMMotor shaft speed right now
motor.get()PercentWhat you asked for. Not a measurement

It is the motor shaft, not the mechanism. A 10 to 1 gearbox means ten motor rotations per output rotation. Position zero means wherever it was last zeroed, which is why an arm has to be homed before a setpoint means anything.

3 PID

closed loopJava
import edu.wpi.first.math.controller.PIDController;

// One controller per mechanism, created ONCE as a field. Never per cycle.
private final PIDController pid = new PIDController(kP, kI, kD);

pid.setTolerance(0.25);                            // what counts as arrived

double out = pid.calculate(currentPosition, target);   // (measurement, setpoint)
motor.set(Math.max(-0.8, Math.min(0.8, out)));         // ALWAYS clamp

boolean there = pid.atSetpoint();                  // reflects the last calculate()
pid.reset();                                       // clear state when a move BEGINS
TermReacts toFix it addressesFailure mode
kPHow far off you are nowDoes the bulk of the workToo small stalls short, too large overshoots
kDHow fast the error is changingDamps the approachTwitchy, can leave an offset
kIError added up over timeFinishes what P cannotWinds up and carries past the target

The tuning recipe. Zero kI and kD. Start kP very small and raise it slowly, doubling each time. Stop when it arrives cleanly, which for most mechanisms is the end of the process. Add kD only if it oscillates, and a small kI only if it stops short. Change one variable at a time.

Two traps that compile perfectly
  • calculate(measurement, setpoint). Measurement first. Swap them and the mechanism drives away from the target and accelerates.
  • The controller does not know your limits. kP of 0.2 at an error of 9 returns 1.8. Clamping is your job, every time.

4 Subsystems

subsystems/IntakeSubsystem.javaJava
import edu.wpi.first.wpilibj2.command.SubsystemBase;

public class IntakeSubsystem extends SubsystemBase {

    // 1) hardware, private and final. the ONLY place this motor is touched
    private final SparkMax roller = new SparkMax(2, MotorType.kBrushless);

    // 2) constructor sets things up
    public IntakeSubsystem() { }

    // 3) your methods
    public void runRoller(double speed) { roller.set(speed); }
    public void stop()                  { roller.set(0); }

    // 4) periodic() runs every 20 ms, ALWAYS, command or no command
    @Override
    public void periodic() { }
}

Exactly one instance per mechanism, created in RobotContainer and handed to every command. Two instances means two motor objects on one CAN ID, and it compiles.

periodic() observes. Commands act. Do not set motors in periodic() unless it is a guard that can only ever stop the mechanism.

5 The command lifecycle

MethodRuns
initialize()Once, when the command begins
execute()Every 20 ms while scheduled
isFinished()Every cycle, after execute(). Return true to end
end(boolean interrupted)Once, whenever it stops
commands/ArmToScoreCommand.javaJava
import edu.wpi.first.wpilibj2.command.Command;

public class ArmToScoreCommand extends Command {

    private final ArmSubsystem arm;
    private static final int TIMEOUT_TICKS = 100;
    private int ticks = 0;

    // The command is HANDED the mechanism. It never builds hardware itself.
    public ArmToScoreCommand(ArmSubsystem arm) {
        this.arm = arm;
        addRequirements(arm);          // only one command drives the arm at a time
    }

    @Override public void initialize()    { ticks = 0; arm.startMove(); }
    @Override public void execute()       { ticks++; arm.goToScore(); }
    @Override public boolean isFinished() { return arm.atSetpoint() || ticks >= TIMEOUT_TICKS; }
    @Override public void end(boolean interrupted) { arm.stop(); }   // ALWAYS stop here
}

Stop the motor in end(), on both paths. It is the only method guaranteed to run when a command stops. And give every command a way to end that does not depend on succeeding, because nothing times out on its own.

6 Button bindings

RobotContainer.javaJava
import edu.wpi.first.wpilibj2.command.button.CommandPS5Controller;
import edu.wpi.first.wpilibj2.command.InstantCommand;

CommandPS5Controller c = new CommandPS5Controller(0);   // 0 = a Driver Station slot

c.cross().onTrue(cmd);          // once, on press. runs to its own end
c.cross().onFalse(cmd);         // once, on release
c.square().whileTrue(cmd);      // while held. interrupted on release
c.triangle().onTrue(new InstantCommand(() -> sub.method()));   // one-off action
ConditionFiresUse for
onTrueOnce, on pressBehaviour that should finish on its own
onFalseOnce, on releaseCleanup on letting go
whileTrueWhile heldBehaviour that should die with the button
whileFalseWhile not heldRare
PS5 face buttons

cross(), circle(), square(), triangle().

.x() is Xbox vocabulary and will not compile against a PS5 controller. The onboarding video says .x(). It is wrong.

7 Command groups

compositionJava
new SequentialCommandGroup(cmd1, cmd2, cmd3);   // in order, each waits for the last
new ParallelCommandGroup(cmdA, cmdB);           // together, ends when ALL end
new WaitCommand(0.5);                           // a timed pause, as a command

A group is a Command. Bind it to a button, nest it inside another group, or use it as an autonomous routine. Two commands requiring the same subsystem cannot be in the same parallel group.

8 Robot modes

Robot.javaJava
robotInit()            // ONCE, at program start. build the RobotContainer here
robotPeriodic()        // every 20 ms, EVERY mode, including disabled

autonomousInit()       // ONCE, when auto begins. schedule the auto command
autonomousPeriodic()   // usually empty

teleopInit()           // ONCE, when teleop begins. CANCEL the auto command
teleopPeriodic()       // usually empty

// The one line that makes the whole framework run, inside robotPeriodic():
CommandScheduler.getInstance().run();
Init runs at the START of a mode

Init runs once when the mode begins. Periodic runs every 20 milliseconds while you are in that mode. There is no method for when a mode ends.

The onboarding video says init is "what happens when it stops." It is not.

9 Output and telemetry

outputJava
System.out.println(value);    // appears in the Driver Station console

Always-on telemetry belongs in a subsystem's periodic(), because that keeps running while the robot is disabled. Put it in execute() and it disappears exactly when you most want it.

12 When something is wrong

Before you read code, eliminate the cheap possibilities. This order matters more under time pressure, not less.

1. Turn the mechanism by hand with the robot off. -> is it mechanically free? 2. Apply a test voltage from the vendor client. -> does the motor turn at all? 3. Does the client see the device on the bus? -> is it addressed correctly? 4. THEN read your code. -> and only then.

The full console triage table, with what each Driver Station symptom means, is in Unit 12 · At the Competition.
