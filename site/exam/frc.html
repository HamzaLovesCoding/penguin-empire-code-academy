Phase 2 Exam

FRC Robot Programming

Prove you are ready for build season. Twenty-five questions, weighted toward the mistakes that actually cost teams matches rather than the ones that fail to compile.

How this is scored, and what it is testing

Five sections, each scored separately so a weak score names the unit to re-read.

Most of these questions are about silent failures. Code that compiles, deploys, enables, and then quietly does the wrong thing. That is deliberate, because the compiler already catches everything else, and a robot that does nothing looks exactly like a robot that was never programmed.

If you scored well, here is what that means

You can create a motor, read a sensor, hold a setpoint under closed-loop control, write a behaviour with a real end condition, own hardware in a subsystem, bind it to a controller, sequence it, drive field-centrically, aim with a camera, and run all of it with nobody touching the controls.

That covers the job. What is left is doing it on real hardware that fights back, which no course can hand you.

And the advice the whole course ends on: do not be afraid to say when something does not make sense. Keep poking at it until it clicks, instead of nodding along.
