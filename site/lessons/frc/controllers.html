1 Why this matters

Cross, not lacrosse

On the call where this team wired up the ChairBot's controller there was real confusion about the button called "the cross." Somebody heard "lacrosse."

It is a funny moment and it sits exactly where the curriculum makes a genuine error. The narrator calls the PS5 X button .x(). It is not.

The PS5 face buttons

On a PS5 controller the four face buttons are cross(), circle(), square() and triangle().

.x() is Xbox vocabulary, alongside .a(), .b() and .y(). It will not compile against a PS5 controller. This line is often copied wrong out of videos, so check it every time.

2 Two controller classes

There are two classes for the same physical controller. The difference between them is most of this lesson.

PS5ControllerCommandPS5Controller
Gives youThe state of buttons and axesTriggers that run a command when a state changes
ReturnsBooleans and doublesTrigger objects you attach commands to
Runs commandsNoYes
Use whenYou need to read a value every cycleAlmost always, in a command-based robot
two constructorsJava
// Plain, reads state:
PS5Controller joystick = new PS5Controller(0);

// Command-based, triggers commands:
CommandPS5Controller joystick2 = new CommandPS5Controller(0);

Same port, two different jobs, and there is nothing wrong with having both in one robot.

The plain class earns its place when you want a continuous conditional read rather than an event. The standard example is worth remembering: while the align button is held, reduce the drive speed. That is not a thing that happens once when the button goes down. It is a condition you check on every cycle, and a command trigger is the wrong shape for it.

3 The number is a port

In new CommandPS5Controller(0), that zero is a port, and what a port is confuses almost everyone at first.

  • The port maps to a slot in the FRC Driver Station application. It is not a physical USB socket on the laptop.
  • In the Driver Station's USB section you drag your plugged-in controller into a port, usually port 0.
  • When your code constructs a controller on port 0, it reads whatever the Driver Station currently has assigned to port 0.
  • Ports identify the controller, not individual buttons. Which button you read is decided in code.
When the controller does nothing

This is why the Joystick indicator in the Driver Station matters, and it is the first thing to check. A controller that is plugged in but not dragged into a port reaches no port at all, so your code on port 0 reads nothing. The fix is a drag and drop, not a code change. Resist the urge to start guessing at port numbers in the constructor.

The port number belongs in your constants file, which is exactly the case the last lesson argued for.

RobotContainer.javaJava
import edu.wpi.first.wpilibj2.command.button.CommandPS5Controller;
import static frc.robot.Constants.OperatorConstants;

private final CommandPS5Controller driver =
    new CommandPS5Controller(OperatorConstants.kDriverControllerPort);

4 The four trigger conditions

The pattern is always controller.button().condition(command).

ConditionFires
onTrueOnce, when the button becomes pressed
onFalseOnce, when it is released
whileTrueRuns while held, and is interrupted on release
whileFalseRuns while not held
Verified syntax · WPILib
bindingsJava
import edu.wpi.first.wpilibj2.command.button.CommandPS5Controller;
import edu.wpi.first.wpilibj2.command.InstantCommand;

CommandPS5Controller controller = new CommandPS5Controller(0);

// PS5 face buttons: cross(), circle(), square(), triangle()
controller.cross().onTrue(intakeCommand);
controller.cross().onFalse(stopCommand);
controller.square().whileTrue(intakeCommand);   // runs only while held

// No full command to hand it? Wrap a call in an InstantCommand, which runs once:
controller.triangle().onTrue(
    new InstantCommand(() -> intakeSub.runRoller(0.7))
);

The () -> is the lambda from Phase 1, and here it means "run this when pressed." InstantCommand is the smallest possible command, and the next lesson covers it properly.

onTrue starts a command and walks away

This is the distinction people get wrong, and the two lines look nearly identical.

onTrue fires once and hands the command over to the scheduler. That command then runs to its own end condition whether or not you are still holding the button. whileTrue ties the command's life to the button.

BindingHold for two secondsRelease after 0.2 seconds
cross().onTrue(armToScore)Arm reaches the setpoint and finishesArm keeps going to the setpoint
cross().whileTrue(armToScore)Arm reaches the setpoint and finishesArm stops where it is, with end(true)

5 Sticks are not buttons

Face buttons are booleans. Sticks are continuous, and reading one is a state read even on a command controller. You get a double from minus one to one.

Verify for current season

The axis getter names, and the import path for the plain PS5Controller, are not in our curriculum's verified boxes. Check the current WPILib documentation before typing them. The CommandPS5Controller import path and the four trigger conditions are verified.

If your team switches to Xbox controllers the equivalents exist with .a(), .b(), .x() and .y(). This course uses PS5 throughout.

One term to know now and use in Unit 9. A stick almost never reads exactly zero at rest, so drive code ignores small values near the centre. That threshold is called a deadband. Without it a robot creeps across the field on its own while nobody is touching anything.

6 Watch the edges fire

PenguinSim has no controller

The sandbox fakes the button with a plain boolean, and the block that detects the press and release is written out in full. On a real robot you never write that block. CommandPS5Controller and the scheduler do it for you. It is spelled out here so you can see what the trigger conditions actually mean.

output
[sim] SparkMax on CAN ID 2 (kBrushless) is alive.
tick 5  cross PRESSED
    onTrue    -> InstantCommand: intake on
        roller -> 0.70
      whileTrue cmd: initialize
        roller -> 0.70
        roller -> 0.70
        roller -> 0.70
        roller -> 0.70
tick 9  cross RELEASED
    onFalse   -> InstantCommand: intake off
        roller -> 0.00
        roller -> 0.00
      whileTrue cmd: end(interrupted=true)

Read that against the table in section 4.

  • onTrue fired once, on tick 5, and never again while the button was held.
  • The whileTrue command executed on every tick from 5 to 8, and not before or after.
  • onFalse fired once, on tick 9.
  • The whileTrue command ended with interrupted=true.
whileTrue commands are almost always interrupted

Look at that last line. isFinished() returned false forever, so the command never finished on its own terms. It was stopped from outside.

That is the normal case for whileTrue, not a failure. It is also exactly why end() must stop the motor, and why the interrupted flag exists at all.

Two experiments worth running.

  • Set RELEASE_AT to 99 so the button is never released. The whileTrue command runs to the end of the loop and its end() never prints, exactly like the unreachable end condition from Unit 7.
  • Change RunIntakeCommand.isFinished() to return true;. Now it ends on its own after one execute, and releasing the button has nothing left to interrupt.

8 Common mistakes

Watch out for these
  • Writing .x() for the X button. On a PS5 controller it is .cross(). This is the error in the source video.
  • Thinking the port is a USB socket. It is a slot in the Driver Station app that you drag a controller into.
  • Thinking the port selects a button. Ports identify the controller. Buttons are chosen in code.
  • Expecting onTrue to run only while held. It fires once and the command finishes on its own terms.
  • Reaching for the command controller to read a trigger's travel. For continuous values read the axes. The command controller's job is turning state changes into commands.
  • Treating a whileTrue command that never finishes as a bug. That is the normal design. Releasing the button interrupts it.

The comments are the deliverable

Four correct lines produced by pattern matching is not this exercise. Being able to say why each binding uses the condition it uses is.

Reveal the solution
RobotContainer.java · bindingsJava
import edu.wpi.first.wpilibj2.command.button.CommandPS5Controller;
import edu.wpi.first.wpilibj2.command.InstantCommand;
import static frc.robot.Constants.OperatorConstants;
import static frc.robot.Constants.IntakeConstants;

private final CommandPS5Controller driver =
    new CommandPS5Controller(OperatorConstants.kDriverControllerPort);

private void configureBindings() {

    // CROSS, onTrue: fire and forget. The arm should finish its move to the
    // scoring setpoint even if the driver's thumb has already moved on.
    driver.cross().onTrue(new ArmToScoreCommand(arm));

    // SQUARE, whileTrue: intake only while held. Release and it stops, because
    // an intake left running eats the next game piece too.
    driver.square().whileTrue(new RunIntakeCommand(intake));

    // CIRCLE, whileTrue: outtake only while held, for the same reason.
    driver.circle().whileTrue(
        new InstantCommand(() -> intake.runRoller(IntakeConstants.kOuttakeSpeed)));

    // TRIANGLE, onTrue: panic stop. One press stops everything, and it must NOT
    // depend on the driver keeping a finger down in an emergency.
    driver.triangle().onTrue(new InstantCommand(() -> {
        intake.stop();
        arm.stop();
    }));
}

Tap versus hold

BindingTapHold for two seconds
cross().onTrue(ArmToScore)Arm still goes all the way to the setpointIdentical. Holding changes nothing
square().whileTrue(RunIntake)Intake runs one cycle, then stopsIntake runs the whole two seconds, then stops
circle().whileTrue(outtake)One cycle of outtakeTwo seconds of outtake
triangle().onTrue(panic)Everything stopsEverything stops, once

Why the panic button is onTrue. In an emergency the one thing you cannot rely on is a human holding a button steadily. A panic stop has to latch on a single press. whileTrue would mean the mechanism resumes the instant a startled thumb slips off the button, which is the worst possible moment for it to start moving again.
