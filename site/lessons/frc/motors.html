Motors & Motor Controllers

Your code never talks to a motor. It talks to a motor controller. That one sentence explains most of the confusion new programmers have with robot hardware.

1 Why this matters

Two students, two manuals

Two new members are given the same task: make the motor spin. One is handed a mechanism with a Neo on it. The other is handed one with a Kraken.

The first opens REV's documentation, writes SparkMax, deploys, and the roller turns. The second copies that code exactly and it does not compile, because a Kraken is not a REV device and the class it needs lives in a different library entirely.

The hardware in your hand decides which documentation is true for you. Nothing in the code tells you that.

2 Two different objects

A motor is the part that spins. It has two power leads and no intelligence at all. Give it power and it turns. Give it more power and it turns harder.

A motor controller is the small box the motor plugs into. It sits on the CAN bus, listens for messages addressed to its CAN ID, and delivers exactly the amount of power those messages ask for.

Here is the sentence that saves people the most confusion:

In code you create the controller, never the motor

new SparkMax(2, MotorType.kBrushless) creates the controller. The Neo bolted to it never appears in your code by name. The only trace of the motor is the argument saying what kind it is.

A Kraken collapses two boxes of the signal path into one. Compare the two setups:

Both still need a unique CAN ID. The bus does not care whether the controller has a motor attached to it or lives inside one.

a REV setupJava
// these two imports come from REVLib, not from WPILib
import com.revrobotics.spark.SparkMax;
import com.revrobotics.spark.SparkLowLevel.MotorType;

// the CONTROLLER object, addressed as CAN ID 2, driving a brushless Neo
SparkMax intakeRoller = new SparkMax(2, MotorType.kBrushless);

For a Kraken you would import from CTRE's Phoenix library instead, where the class is called TalonFX and lives at com.ctre.phoenix6.hardware.TalonFX. The way you command it is not identical to REV's, which is exactly the point of this lesson. Read CTRE's documentation rather than assuming the REV method names carry over.

Verify for current season

Vendor class names and import paths move between seasons. REVLib renamed CANSparkMax to SparkMax, and CTRE's Phoenix 6 replaced most of the Phoenix 5 API. Confirm every class name against the version of the library your project actually pulls in, which is a thing you will learn to check in Vendor Libraries.

4 Brushed and brushless

Motors come in two families.

  • Brushed. Physical contacts inside the motor, called brushes, rub against a rotating part to switch the current. Older, simpler, cheaper, and they wear out.
  • Brushless. The switching is done electronically by the controller. More efficient, longer lasting, and the current standard on FRC robots.

Neos and Krakens are both brushless. That is why the argument you will type more than any other this season is MotorType.kBrushless.

This argument is not cosmetic

REV's documentation is direct about why motor type has to be set in the constructor rather than in a configuration object: driving a brushless motor in brushed mode can permanently damage the motor. Getting this argument wrong is one of the few software mistakes that destroys hardware immediately.

5 Why one mechanism has four motors

New programmers assume one mechanism means one motor. Two reasons that is wrong.

Torque. A mechanism may need more force than one motor can give. The team's rule from Unit 4 is a design principle here: if you need more force, add a motor rather than pushing one harder. A motor run near full power is a motor you are about to replace.

Independent control. Some mechanisms need separate sides. The team's ChairBot drove with two sides, two wheels per side, and two motors per side, so four motors for one drivetrain.

Drivetrain.javaJava
// four motors, four unique CAN IDs, one mechanism
SparkMax leftMotor1  = new SparkMax(2, MotorType.kBrushless);
SparkMax leftMotor2  = new SparkMax(3, MotorType.kBrushless);
SparkMax rightMotor1 = new SparkMax(4, MotorType.kBrushless);
SparkMax rightMotor2 = new SparkMax(5, MotorType.kBrushless);

Notice every ID is different. Two devices sharing an ID on one bus is a real and confusing failure, and CAN IDs covers exactly what happens.

When a mechanism has several motors, one method usually writes to all of them at once:

Drivetrain.javaJava
// one call, both motors on that side
public void setLeftSide(double speed) {
    leftMotor1.set(speed);
    leftMotor2.set(speed);
}

That is the shape you will write for real in Unit 7, when this becomes a Subsystem.

PenguinBot's swerve drivetrain takes this further. It has four modules, and each module has one motor to drive the wheel and one motor to steer it. That is eight motors on one mechanism, which is a large part of why swerve gets its own unit and why nobody hand writes the math for it.

6 Reading the right manual

The practical skill from this lesson is a reflex with three steps.

  1. Identify the hardware physically. Read the label on the device.
  2. Work out which vendor makes it.
  3. Open that vendor's documentation, not a search engine and not your friend's code.

REV documents the SparkMax and the Neo. CTRE documents the Kraken and the Phoenix library. WPILib documents everything that is not vendor specific, including the roboRIO, the Driver Station, and the command based framework you meet in Unit 7.

8 Common mistakes

Watch out for these
  • Calling a SparkMax a motor. It is a controller. The motor plugged into it is a Neo, and the Neo never appears in your code.
  • Assuming all motors use the same class. A Neo goes through REV's SparkMax. A Kraken goes through CTRE's Phoenix library. Same idea, different library, different method names.
  • Thinking a Kraken needs a SparkMax. Its controller is built in. CAN runs straight through the motor.
  • One mechanism, one motor. The ChairBot drove each side with two motors, and a swerve drivetrain uses eight.
  • Thinking kBrushless describes the controller. It describes the motor you plugged in. A Neo is brushless, so you tell the SparkMax that.
