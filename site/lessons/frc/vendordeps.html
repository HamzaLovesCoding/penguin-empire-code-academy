1 Why this matters

The import that will never resolve

The team sat down to program the ChairBot with the Jaguar motor controllers they already owned. They wrote the import for the Jaguar class and it would not resolve. Jaguars had been discontinued and removed from current WPILib. The class was not deprecated or renamed. It was gone.

That incident is this whole lesson. Two very different problems produce the same red squiggle:

  1. The class was removed from the library. Nothing you type fixes that.
  2. You have not installed the library it lives in. Thirty seconds to fix.

Telling them apart is the skill. The ChairBot itself shipped on last year's code from GitHub, which still had working Jaguar support, edited for the new robot. Old code is a legitimate answer to a removed API.

2 What a vendor library is

WPILib is the core framework. It knows about the roboRIO, the Driver Station, timing, math, and the command based structure. It knows nothing at all about REV's or CTRE's hardware.

Each hardware vendor ships a vendor library so their devices can be used from Java.

LibraryFromGives you
WPILibFIRST / WPIPIDController, Timer, SubsystemBase, Command
REVLibREV RoboticsSparkMax, MotorType, RelativeEncoder
PhoenixCTRETalonFX and everything else for Krakens

Three facts about vendor libraries that explain almost every confusing situation you will hit:

  • They are installed per project. A new project starts with none.
  • The installation is recorded in a JSON file inside the project's vendordeps/ folder.
  • That record pins a version, which is why two of your team's repositories can disagree about what a class is called.

3 Reading a package root

You can tell where a class comes from without looking anything up. Read the start of the package name.

imports, decodedJava
import edu.wpi.first.math.controller.PIDController;   // edu.wpi.first = WPILib, always present
import com.revrobotics.spark.SparkMax;                // com.revrobotics = REV, needs REVLib
import com.ctre.phoenix6.hardware.TalonFX;            // com.ctre = CTRE, needs Phoenix

When an import will not resolve, read the root first. edu.wpi.first failing is unusual and usually means a broken project. com. anything failing almost always means a vendor library is not installed.

4 Installing REVLib

WPILib's VS Code has a vendor dependency manager. There are two routes and both end in the same place.

From the list. Open the WPILib vendor dependencies view, find REVLib under the available dependencies, and install it. Confirm it then appears under installed dependencies. This is the route the team uses, and it needs no URL.

From a URL. Run Manage Vendor Libraries from the command palette, choose Install new library (online), and paste the vendor's JSON URL. REV's is:

REVLib · online install URL
https://software-metadata.revrobotics.com/REVLib-2026.json
Verify for current season

That URL has the season in it. Next year it will be a different number, and using an old one silently installs an old library. Take the URL from REV's current documentation rather than from a lesson, a forum post, or a teammate's notes.

After installing, rebuild. Then type SparkMax and take the autocomplete. The import appears at the top of the file on its own:

IntakeSubsystem.javaJava
// added for you when you accept the autocomplete
import com.revrobotics.spark.SparkMax;
import com.revrobotics.spark.SparkLowLevel.MotorType;

5 What the vendordep file is

Installing a vendor library does not copy source code into your project. It writes one short JSON file into vendordeps/ naming the library, its version, and where Gradle should fetch it from. Gradle downloads the actual library at build time.

Two consequences worth knowing now:

  • You never edit vendor code. If you find yourself in a vendor library's source, you have gone the wrong way.
  • The vendordeps/ folder belongs in version control. Sharing your project without it means the next person's build fails on imports that work perfectly for you.
vendor library
Code a hardware vendor ships so their devices can be controlled from Java.
vendordep
The JSON record in your project that says which vendor libraries are installed and at what version.
REVLib
REV's library. The home of SparkMax, MotorType and RelativeEncoder.
Phoenix
CTRE's library, used for Krakens and other CTRE devices.

6 Missing, or gone for good

Back to the two problems from the top of the page. Here is how to tell them apart in under a minute.

CheckNot installedRemoved from the library
Is the library in vendordeps/?NoYes
Do the vendor's other classes resolve?No, none of themYes, just not this one
Is the class in the vendor's current documentation?YesNo
What fixes itInstall the vendordep and rebuildDifferent hardware, a different class, or an older season's project

The middle row is the fastest test. If every class from a vendor is red, the library is missing. If one class out of many is red, that class moved or was removed.

8 Common mistakes

Watch out for these
  • Thinking SparkMax is part of WPILib. It is REV's class from REV's library. WPILib knows nothing about SparkMaxes until you install REVLib.
  • "I installed REVLib last time." Vendordeps are per project. Every new project starts empty.
  • Reading a red squiggle as a typo. Check whether the library is installed before you doubt your spelling, and read the package root.
  • Assuming last year's code compiles this year. Last year's project pins last year's library. CANSparkMax became SparkMax, and Jaguar support disappeared entirely.
  • Expecting to edit the vendor's code. Installing writes a small JSON record. Gradle fetches the library at build time and you never touch it.
  • Leaving vendordeps/ out of version control. The next person to clone your project gets imports that fail for no visible reason.
Build it · PenguinBot

Make SparkMax resolve

You created the PenguinBot project last lesson and it builds clean. It cannot talk to a single REV motor yet. Step one is to look at the failure before you fix it.

  1. Open PenguinBot. In RobotContainer.java, type SparkMax somewhere temporary and confirm it does not resolve.
  2. Open the WPILib vendor dependencies view and install REVLib.
  3. Confirm REVLib now appears under installed dependencies.
  4. Open the new file in the project's vendordeps/ folder and read it. It is short.
  5. Rebuild, retype SparkMax, and take the autocomplete.
  6. Confirm the import appeared at the top of the file without you typing it.
  7. Delete your temporary line and build again. Clean.
What you should have seen

Before installing, SparkMax is red and the editor says it cannot be resolved to a type. After installing REVLib and rebuilding, the same word autocompletes and this line appears at the top of the file:

RobotContainer.java
import com.revrobotics.spark.SparkMax;

The vendordeps/ folder now holds a JSON file naming the library, its version, and where Gradle fetches it from. That file is the entire installation.

You deleted the test line on purpose. PenguinBot's motors get created inside a subsystem, not in RobotContainer. Unit 3 shows where things belong and Unit 4 writes the real one.
