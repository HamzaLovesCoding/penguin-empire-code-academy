Fields, Constructors & this

A constructor runs automatically the moment new builds an object, so every field can be set in one call instead of several separate lines.

1 The problem with plain fields

Lesson 20 built an object, then set each field with a separate dot-assignment line. Forgetting one of those lines is easy, and Java never warns you. The field just keeps its default value.

Main.javaJava
Flywheel shooter = new Flywheel();
shooter.canId = 5;
// name never set

System.out.println(shooter.name + " on CAN " + shooter.canId);
output
null on CAN 5

The program compiles and runs. It just carries a bug that shows up later, usually far from this line. A constructor closes that gap by setting every field at the same instant the object is built.

2 A constructor runs when new does

A constructor is a block of code that runs automatically every time new builds an object. It looks like a method with two differences. It has no return type, not even void, and its name must match the class name exactly.

Main.javaJava
class Flywheel {
    int canId;
    String name;

    Flywheel(int id, String flywheelName) {
        canId = id;
        name = flywheelName;
    }
}

public class Main {
    public static void main(String[] args) {
        Flywheel shooter = new Flywheel(5, "Shooter Flywheel");
        System.out.println(shooter.name + " on CAN " + shooter.canId);
    }
}
output
Shooter Flywheel on CAN 5

Both fields are set in one call. There is no way to build a Flywheel without supplying an id and a flywheelName, because those are exactly the values the constructor asks for.

Writing any constructor removes the empty one

Before you write a constructor, new Flywheel() with no arguments compiles on its own. Once you declare Flywheel(int id, String flywheelName), that empty version is gone. Calling new Flywheel() now gives a compiler error, because no constructor matches zero arguments.

3 The keyword this

A common style names constructor parameters exactly the same as the fields they fill. That reads well, but it creates a name clash inside the constructor body.

Main.javaJava
class Flywheel {
    int canId;
    String name;

    Flywheel(int canId, String name) {
        canId = canId;   // assigns the parameter to itself
        name = name;     // same problem
    }
}

Inside the constructor body, a plain canId means the parameter, since it is the closer variable. This is the same rule the scope lesson covered for any two variables that share a name. canId = canId; assigns the parameter to itself and never touches the field. Building a Flywheel this way leaves both fields at their default values.

output
null on CAN 0

this refers to the object currently being built. Writing this.canId reaches the field, no matter what the parameter is called.

Main.javaJava
class Flywheel {
    int canId;
    String name;

    Flywheel(int canId, String name) {
        this.canId = canId;
        this.name = name;
    }
}

Now this.canId names the field on the left, and the plain canId on the right names the parameter that was just passed in. The value moves from parameter into field, and new Flywheel(5, "Shooter Flywheel") produces the same object as the version in section 2.

this is only needed when names clash

Section 2 used id and flywheelName as parameter names and never needed this. It only matters when a parameter shares a name with a field. Either style compiles. Matching names plus this is the more common style in real Java code.

4 Multiple constructors

You already overload methods, same name, different parameter lists. A constructor overloads the same way, since its name is fixed to the class name anyway.

Main.javaJava
class Flywheel {
    int canId;
    String name;
    double targetRPM;

    Flywheel(int canId, String name, double targetRPM) {
        this.canId = canId;
        this.name = name;
        this.targetRPM = targetRPM;
    }

    Flywheel(int canId, String name) {
        this.canId = canId;
        this.name = name;
        this.targetRPM = 4000;
    }
}

public class Main {
    public static void main(String[] args) {
        Flywheel shooter = new Flywheel(5, "Shooter Flywheel", 5200);
        Flywheel climber = new Flywheel(6, "Climber Flywheel");

        System.out.println(shooter.name + " target " + shooter.targetRPM);
        System.out.println(climber.name + " target " + climber.targetRPM);
    }
}
output
Shooter Flywheel target 5200.0
Climber Flywheel target 4000.0

Java picks the constructor whose parameter list matches the call. Three arguments call the first constructor. Two arguments call the second, which fills targetRPM with a sensible default instead of leaving it at 0.0.

7 Common mistakes

Watch out for these
  • Giving a constructor a return type. Even void turns it into an ordinary method that never runs automatically.
  • Spelling the constructor name differently from the class name, even by one letter.
  • Writing canId = canId; when the parameter and field share a name, instead of this.canId = canId;.
  • Calling new ClassName() after adding a constructor with parameters, and being surprised it no longer compiles.
  • Writing two constructors with the exact same parameter types, which the compiler rejects as a duplicate.
Exercise

A Constructor For Motor

Rebuild the Motor class from lesson 20 so it can never be created with missing data.

  1. Give Motor a constructor that takes canId and name and assigns both fields using this.
  2. Create leftDrive and rightDrive with a single constructor call each, no separate assignment lines.
  3. Print both in the form name on CAN canId.
  4. Bonus: add a second constructor that takes only canId and sets name to "Unnamed Motor".
Show one possible solution
solution · Main.java
class Motor {
    int canId;
    String name;

    Motor(int canId, String name) {
        this.canId = canId;
        this.name = name;
    }

    Motor(int canId) {
        this.canId = canId;
        this.name = "Unnamed Motor";
    }
}

public class Main {
    public static void main(String[] args) {
        Motor leftDrive = new Motor(1, "Left Drive");
        Motor rightDrive = new Motor(2, "Right Drive");

        System.out.println(leftDrive.name + " on CAN " + leftDrive.canId);
        System.out.println(rightDrive.name + " on CAN " + rightDrive.canId);

        Motor spare = new Motor(9);
        System.out.println(spare.name + " on CAN " + spare.canId);
    }
}
output
Left Drive on CAN 1
Right Drive on CAN 2
Unnamed Motor on CAN 9

Neither object can exist with a missing canId. The one-argument constructor still guarantees a sensible name instead of leaving it null.
