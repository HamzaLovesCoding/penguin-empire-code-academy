Interfaces & Abstract Classes

An interface is a list of methods a class promises to provide. It says what a class can do and nothing about how.

1 Declaring an interface

Use the word interface instead of class. Methods have no body, just a signature and a semicolon.

Main.javaJava
interface Stoppable {
    void emergencyStop();
}

There are no fields and no constructor. An interface holds no data. Methods are automatically public, so the word public is left out.

2 implements

A class promises to provide the methods with implements.

Main.javaJava
class Compressor implements Stoppable {
    @Override
    public void emergencyStop() {
        System.out.println("Compressor off");
    }
}

Leave out emergencyStop and the class does not compile. The interface is a requirement the compiler enforces, the same way an abstract method was in the previous lesson.

3 Using it as a type

An interface can be used as a variable type. Any class that implements it fits.

Main.javaJava
Compressor c = new Compressor();
Stoppable s = c;
s.emergencyStop();
output
Compressor off

This is the polymorphism from the previous lesson, without any inheritance. A Stoppable[] can hold a compressor, a motor and a light, none of which share a parent class.

4 Several interfaces at once

A class can extend only one class. It can implement as many interfaces as it likes, separated by commas.

Main.javaJava
class Flywheel extends Subsystem implements Stoppable, Reportable {
    // must provide every method from both interfaces
}

This is the main practical difference. Inheritance gives a class one parent. Interfaces let a class take on any number of separate capabilities.

5 default methods

An interface method marked default may have a body. Classes get it automatically and can override it if they want.

Main.javaJava
interface Stoppable {
    void emergencyStop();

    default void log() {
        System.out.println("logging a stoppable device");
    }
}
output of c.emergencyStop() then c.log()
Compressor off
logging a stoppable device

Compressor never declared log. It came from the interface.

6 Interface or abstract class

Abstract class
Use when the classes are genuinely related and share data or code. It can hold fields, constructors and normal methods. A class can extend only one.
Interface
Use when unrelated classes need to be treated the same way. It holds no data. A class can implement many.

A useful test. If the sentence is “a Flywheel is a Subsystem”, that is inheritance. If the sentence is “a Flywheel can be stopped”, that is an interface.

9 Common mistakes

Watch out for these
  • Writing extends where you need implements.
  • Forgetting to make the implementing method public. Interface methods are public, and an implementation cannot be less visible.
  • Giving an interface method a body without default.
  • Trying to put a field in an interface. It holds no data.
  • Using an interface when the classes really are related and share code. An abstract class is the better fit there.
Exercise

One Switch, Three Devices

Shut down three unrelated devices with one loop.

  1. Declare a Stoppable interface with emergencyStop() and a default method log().
  2. Write Compressor, StatusLight and DriveMotor, none of which extend anything, all implementing Stoppable.
  3. Put all three in a Stoppable[] and loop over it calling log() then emergencyStop().
  4. Bonus: override log() in one of the three and see which version runs.
Show one possible solution
solution · Main.java
interface Stoppable {
    void emergencyStop();

    default void log() {
        System.out.println("logging a stoppable device");
    }
}

class Compressor implements Stoppable {
    @Override public void emergencyStop() { System.out.println("Compressor off"); }
}

class StatusLight implements Stoppable {
    @Override public void emergencyStop() { System.out.println("Status light off"); }
    @Override public void log() { System.out.println("logging the status light"); }
}

class DriveMotor implements Stoppable {
    @Override public void emergencyStop() { System.out.println("Drive motor at zero"); }
}

public class Main {
    public static void main(String[] args) {
        Stoppable[] devices = { new Compressor(), new StatusLight(), new DriveMotor() };

        for (Stoppable d : devices) {
            d.log();
            d.emergencyStop();
        }
    }
}
output
logging a stoppable device
Compressor off
logging the status light
Status light off
logging a stoppable device
Drive motor at zero

The three classes share no parent. StatusLight overrode log() and the other two used the default. The loop treats all three identically.
