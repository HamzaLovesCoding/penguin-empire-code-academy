Parameters & Return Values

A method becomes useful when it can work on values you give it and hand an answer back. That is what parameters and return values do.

1 Parameters

A parameter is a variable declared in the parentheses of a method. It receives a value each time the method is called.

Main.javaJava
static void reportSubsystem(String name, int canId) {
    System.out.println(name + " on CAN " + canId);
}

public static void main(String[] args) {
    reportSubsystem("Intake", 2);
    reportSubsystem("Shooter", 5);
}
output
Intake on CAN 2
Shooter on CAN 5

One method, two different results. The values in the call are the arguments. The variables in the declaration are the parameters. The names get used loosely in conversation and the distinction rarely matters.

2 More than one parameter

Separate them with commas. Each one needs its own type, even when two parameters share a type.

Main.javaJava
static void setSpeeds(double left, double right) { }   // correct
static void setSpeeds(double left, right) { }          // does not compile

Arguments are matched by position, not by name. The first argument fills the first parameter. Swapping two arguments of the same type compiles fine and produces the wrong answer.

3 Returning a value

Replace void with a type, then use return to hand a value back.

Main.javaJava
static double clamp(double value) {
    return Math.min(0.8, Math.max(-0.8, value));
}

public static void main(String[] args) {
    System.out.println(clamp(0.95));
    System.out.println(clamp(-1.0));
    System.out.println(clamp(0.5));
}
output
0.8
-0.8
0.5

The declared type and the returned value must match. A method declared double must return a double on every path out of the method, or it will not compile.

The clamp is now a name

In lesson 4 that expression was written out in full. Now it has a name and lives in one place. In Phase 2 you will call a method exactly like this on the output of a PID controller.

4 Catching what comes back

A returned value is thrown away unless you store it, print it, or use it in a larger expression.

Main.javaJava
clamp(0.95);                        // the answer is discarded
double safe = clamp(0.95);          // stored
System.out.println(clamp(0.95));    // printed
motorSet(clamp(0.95));              // passed straight on

This is the same rule as toUpperCase() in lesson 5. A method that returns a value and is called on its own line usually means a bug.

5 return ends the method

return hands the value back and leaves immediately. Any code after it in that path does not run.

Main.javaJava
static boolean isSafe(double speed) {
    if (speed > 0.8) {
        return false;
    }
    if (speed < -0.8) {
        return false;
    }
    return true;
}

Three exits, one value each. As soon as one return runs the method is finished, so the last line only happens when both checks passed.

8 Common mistakes

Watch out for these
  • Calling a returning method on its own line, so the answer is discarded.
  • Declaring a return type and forgetting to return on some path, which gives missing return statement.
  • Returning a value from a void method.
  • Leaving out the type on the second parameter.
  • Passing arguments in the wrong order when they share a type. Nothing is reported.
  • Writing code after return in the same branch, which never runs.
Exercise

A Small Robot Maths Library

Write four methods that each take values and return an answer.

  1. clamp(double value) returns the value held between −0.8 and 0.8.
  2. ticksToDegrees(int ticks, int perRotation) returns the angle.
  3. isSafe(double speed) returns a boolean.
  4. batteryPercent(double volts) returns the percentage of 12.6 volts.
  5. Bonus: call clamp inside another method rather than in main.
Show one possible solution
solution · Main.java
public class Main {

    static double clamp(double value) {
        return Math.min(0.8, Math.max(-0.8, value));
    }

    static double ticksToDegrees(int ticks, int perRotation) {
        return (double) ticks / perRotation * 360;
    }

    static boolean isSafe(double speed) {
        return speed >= -0.8 && speed <= 0.8;
    }

    static double batteryPercent(double volts) {
        return volts / 12.6 * 100;
    }

    public static void main(String[] args) {
        System.out.println("clamp(0.95)     = " + clamp(0.95));
        System.out.println("degrees(90,20)  = " + ticksToDegrees(90, 20));
        System.out.println("isSafe(0.9)     = " + isSafe(0.9));
        System.out.printf("battery(11.4)   = %.1f%%%n", batteryPercent(11.4));
    }
}
output
clamp(0.95)     = 0.8
degrees(90,20)  = 1620.0
isSafe(0.9)     = false
battery(11.4)   = 90.5%

Every one of these is a single line of logic with a name attached. That is what most of a robot codebase looks like.
