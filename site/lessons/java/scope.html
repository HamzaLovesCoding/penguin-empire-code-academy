Lesson 14

Scope & the Call Stack

A variable does not exist everywhere. It exists inside the braces where it was declared and nowhere else. Knowing the rule explains a whole class of errors.

1 Scope is the braces

A variable exists from the line that declares it to the closing brace of the block it is in. After that it is gone, and using its name gives cannot find symbol.

does not compile
if (true) {
    int inside = 1;
}
System.out.println(inside);
error
Main.java:4: error: cannot find symbol

You met that message in lesson 6 as the typo error. This is its other cause. The name is spelled correctly and the variable really was declared, but not in a place this line can see.

2 Loop variables

A variable declared in a for header belongs to the loop and disappears when the loop ends.

does not compile
for (int i = 0; i < 3; i++) {
}
System.out.println(i);

This is why a running total is declared before the loop. Anything declared inside vanishes at the closing brace.

3 Each method has its own

Variables declared inside a method are called local variables. Another method cannot see them, and two methods can use the same name with no connection at all.

Main.javaJava
static double average(double a, double b) {
    double sum = a + b;      // sum exists only in here
    return sum / 2;
}

Parameters follow the same rule. a and b exist only inside average.

4 Values are copied in

When you pass a number to a method, the method receives a copy. Changing the parameter inside the method does not touch the caller's variable.

Main.javaJava
static void addOne(int speed) {
    speed = speed + 1;
    System.out.println("inside addOne, speed = " + speed);
}

public static void main(String[] args) {
    int speed = 5;
    addOne(speed);
    System.out.println("back in main, speed = " + speed);
}
output
inside addOne, speed = 6
back in main, speed = 5

Two variables named speed exist here and they are unrelated. This is the same rule as int b = a; in lesson 3, which copied a value rather than linking two boxes.

To change a value, return it

A method cannot reach back and edit a number you passed in. Return the new value and store it, as in speed = addOne(speed);. Objects behave differently, and Unit J5 covers that.

5 The call stack

Java keeps a list of which method called which. When main calls runDiagnostics, which calls checkBus, the list has three entries. Each entry holds that method's own local variables.

When a method finishes, its entry is removed and its local variables are gone. That is the mechanism behind everything in the sections above.

6 Reading a full trace

Lesson 6 promised an explanation of the at lines. This is it. Each at line is one entry in the call stack.

console
Exception in thread "main" java.lang.ArithmeticException: / by zero
        at Main.checkBus(Main.java:13)
        at Main.runDiagnostics(Main.java:15)
        at Main.main(Main.java:23)

Read it from the bottom up as the story of how you got there. main on line 23 called runDiagnostics. That method on line 15 called checkBus. The crash happened inside checkBus on line 13.

The top line is where it broke. The lines below tell you how execution arrived there, which matters when a method is called from several places.

9 Common mistakes

Watch out for these
  • Using a variable after the block that declared it has closed.
  • Expecting a method to change a number you passed in. Return the value instead.
  • Declaring a running total inside the loop.
  • Reading only the top line of a stack trace when the useful context is below it.
  • Assuming two variables with the same name in different methods are connected.
Exercise

Make the Change Stick

A method is meant to raise a speed but the change never survives. Fix it.

  1. Run the starter and confirm speed is still 0.5 afterwards.
  2. Change boost so it returns the new value instead of assigning to the parameter.
  3. Store the result back into speed in main.
  4. Bonus: add a second method that calls boost, then trigger a crash inside it and read the three frame trace.
Show one possible solution
solution · Main.java
public class Main {

    static double boost(double speed) {
        return speed + 0.2;
    }

    public static void main(String[] args) {
        double speed = 0.5;
        speed = boost(speed);
        System.out.println("speed = " + speed);
    }
}
output
speed = 0.7

The method no longer tries to reach into main. It computes an answer and hands it back, and the caller decides what to do with it.
