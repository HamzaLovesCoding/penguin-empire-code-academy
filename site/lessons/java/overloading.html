Method Overloading

Java allows several methods to share one name as long as they take different parameters. The arguments you pass decide which one runs.

1 Same name, different parameters

Three methods called setSpeed can coexist as long as their parameter lists differ. Java picks the one that matches the call.

Main.javaJava
static void setSpeed(double speed) {
    System.out.println("one motor at " + speed);
}

static void setSpeed(double left, double right) {
    System.out.println("left " + left + ", right " + right);
}

static void setSpeed(String name, double speed) {
    System.out.println(name + " at " + speed);
}

public static void main(String[] args) {
    setSpeed(0.7);
    setSpeed(0.7, -0.7);
    setSpeed("Intake", 0.7);
}
output
one motor at 0.7
left 0.7, right -0.7
Intake at 0.7

All three calls use one name. Java chose between them by counting the arguments and checking their types.

2 What makes an overload valid

The parameter lists must differ in the number of parameters or in their types.

Different count
setSpeed(double) and setSpeed(double, double). Valid.
Different types
setSpeed(double) and setSpeed(String, double). Valid.
Different names only
setSpeed(double a) and setSpeed(double b). Not valid. Parameter names are not part of the signature.
Renaming a parameter is not an overload

Two methods that take one double each are the same method as far as Java is concerned, whatever the parameters are called. The compiler reports method is already defined.

3 The return type does not count

Changing only the return type does not create an overload.

does not compile
static int    read(String name) { return 1; }
static double read(String name) { return 1.0; }

Java chooses the method before it looks at what you do with the result, so a call to read("arm") would be ambiguous. Only the parameters can tell overloads apart.

4 You have seen this already

System.out.println is overloaded. There is a version for String, one for int, one for double, one for boolean, and a version with no parameters that just ends the line.

That is why println handles every type you have thrown at it without complaint, and why System.out.println() on its own is legal.

Math.max is overloaded too, with versions for int and double. That is why Math.max(3, 9) gives 9 while Math.max(3.0, 9.0) gives 9.0.

7 Common mistakes

Watch out for these
  • Changing only the return type, which gives method is already defined.
  • Changing only a parameter name, which is the same signature.
  • Overloading methods that do unrelated things. Same name should mean same idea.
  • Creating so many overloads that a reader cannot tell which one a call selects.
  • Expecting Java to pick by what you assign the result to. It picks from the arguments only.
Exercise

One Name, Three Uses

Build a small set of overloads for reporting a subsystem.

  1. report(String name) prints the name and OK.
  2. report(String name, int canId) adds the CAN ID.
  3. report(String name, int canId, double position) adds the position, printed to two decimal places.
  4. Call all three from main.
  5. Bonus: make the shorter versions call the longest one rather than repeating the printing code.
Show one possible solution
solution · Main.java
public class Main {

    static void report(String name) {
        System.out.println(name + " OK");
    }

    static void report(String name, int canId) {
        System.out.println(name + " OK (CAN " + canId + ")");
    }

    static void report(String name, int canId, double position) {
        System.out.printf("%s OK (CAN %d) at %.2f%n", name, canId, position);
    }

    public static void main(String[] args) {
        report("Intake");
        report("Shooter", 5);
        report("Arm", 3, 8.9732);
    }
}
output
Intake OK
Shooter OK (CAN 5)
Arm OK (CAN 3) at 8.97

One idea, three levels of detail, one name to remember. That is what overloading is for.
