Encapsulation (public / private)

private hides a field so nothing outside the class can set it directly. public methods become the only way in, and a method can check a value before it is ever stored.

1 Why hide fields

Every field in the last four lessons could be set directly from outside the class, to any value at all, with no check. Nothing stops a caller from setting a target speed the flywheel could never safely reach.

Main.javaJava
Flywheel shooter = new Flywheel();
shooter.canId = 5;
shooter.name = "Shooter Flywheel";
shooter.targetRPM = 5000;

shooter.targetRPM = -500;
System.out.println(shooter.targetRPM);
output
-500.0

The program compiles and runs without complaint. A negative target speed makes no physical sense, and Java has no way to know that unless the class itself refuses to store it.

2 private keeps a field inside the class

Adding private to a field means only code written inside that same class can read or assign it. Every other class, including Main, loses direct access completely.

Main.javaJava
class Flywheel {
    private int canId;
    private String name;
    private double targetRPM;
}

public class Main {
    public static void main(String[] args) {
        Flywheel shooter = new Flywheel();
        shooter.targetRPM = -500;
        System.out.println(shooter.targetRPM);
    }
}
output
error: targetRPM has private access in Flywheel

The line that used to compile now fails before the program ever runs. Main is outside Flywheel, so shooter.targetRPM is no longer reachable from there.

3 public methods are the only way in

A private field still needs some way to be set and read. The constructor and the methods a class exposes as public become the only door in. Everything you wrote in lessons 21 and 22, the constructor, spinUp(), stop(), isAtSpeed(), keeps working, since code inside Flywheel can always reach its own private fields.

Main.javaJava
class Flywheel {
    private static final double MAX_RPM = 6000;

    private int canId;
    private String name;
    private double targetRPM;
    private double currentRPM;

    public Flywheel(int canId, String name, double targetRPM) {
        this.canId = canId;
        this.name = name;
        this.targetRPM = Math.min(targetRPM, MAX_RPM);
        this.currentRPM = 0;
    }

    public void spinUp() {
        currentRPM = targetRPM;
    }

    public void stop() {
        currentRPM = 0;
    }

    public boolean isAtSpeed() {
        return Math.abs(currentRPM - targetRPM) <= 50;
    }
}

The constructor is public so any other class can still build a Flywheel. The fields underneath it are private, so no other class can reach past the constructor and the methods to touch them directly.

This pattern has a name

Hiding a class's fields behind its own methods is called encapsulation. The class decides exactly what the outside world is allowed to do to its data.

4 Getters return a value

A private field with no way to read it is close to useless outside the class. A getter is a small public method whose only job is returning one field's value.

Main.javaJava
public double getCurrentRPM() {
    return currentRPM;
}

public double getTargetRPM() {
    return targetRPM;
}

The naming pattern is always get followed by the field name with a capital letter. shooter.getTargetRPM() reads the field from outside the class without ever exposing it to direct assignment.

5 A setter can check before assigning

A setter is a public method that assigns a private field, and unlike a plain field it can check the value first.

Main.javaJava
public void setTargetRPM(double targetRPM) {
    this.targetRPM = Math.min(targetRPM, MAX_RPM);
}
Main.java
Flywheel shooter = new Flywheel(5, "Shooter Flywheel", 5000);

System.out.println(shooter.getTargetRPM());
shooter.setTargetRPM(9000);
System.out.println(shooter.getTargetRPM());
output
5000.0
6000.0

setTargetRPM(9000) never lets targetRPM exceed MAX_RPM. A plain public field could never do that. It only ever stores exactly what it is given.

8 Common mistakes

Watch out for these
  • Marking a field private and never adding a getter or setter, leaving nothing outside the class able to reach it at all.
  • Writing a setter that assigns the field with no check, which brings back the exact problem encapsulation was meant to fix.
  • Trying to read or set a private field from another class, which gives field has private access in ClassName.
  • Marking the constructor private by mistake, which stops every other class from ever building the object with new.
  • Naming a getter something other than get plus the field name, which breaks the convention every other Java class expects.
Exercise

Locking Down Motor

Encapsulate the Motor class from earlier lessons.

  1. Make canId and name private.
  2. Make the constructor public, assigning both fields as before.
  3. Add public getters getCanId() and getName().
  4. Add public void setCanId(int newCanId) that only assigns when newCanId is 0 or greater, and otherwise leaves canId unchanged.
  5. Bonus: create a Motor, print it through the getters, call setCanId with a negative number, and print it again to confirm nothing changed.
Show one possible solution
solution · Main.java
class Motor {
    private int canId;
    private String name;

    public Motor(int canId, String name) {
        this.canId = canId;
        this.name = name;
    }

    public int getCanId() {
        return canId;
    }

    public String getName() {
        return name;
    }

    public void setCanId(int newCanId) {
        if (newCanId >= 0) {
            canId = newCanId;
        }
    }
}

public class Main {
    public static void main(String[] args) {
        Motor leftDrive = new Motor(1, "Left Drive");

        System.out.println(leftDrive.getName() + " on CAN " + leftDrive.getCanId());

        leftDrive.setCanId(3);
        System.out.println(leftDrive.getName() + " on CAN " + leftDrive.getCanId());

        leftDrive.setCanId(-7);
        System.out.println(leftDrive.getName() + " on CAN " + leftDrive.getCanId());
    }
}
output
Left Drive on CAN 1
Left Drive on CAN 3
Left Drive on CAN 3

setCanId(-7) changes nothing, because the check inside the method rejects it before canId is ever touched. A plain public field has no way to refuse a value like that.
