Classes & Objects

A class groups related data and behavior under one name. An object is a specific instance built from that class. Everything from here to the end of Phase 1 is built out of these two ideas.

1 A class is a blueprint

A class groups related data under one name. The data lives in fields, declared the same way you have always declared a variable, except a field is written inside the class body and outside any method.

the shape
class Flywheel {
    int canId;
    String name;
}

This class by itself does nothing and prints nothing. It only describes what a Flywheel is made of, an integer called canId and a piece of text called name. No Flywheel exists yet.

2 An object is an instance

An object is a specific value built from a class. It carries its own copy of every field the class declares. The class is the description. The object is the actual thing described.

Class
The declaration. Written once, in a file.
Object
A value built from a class at run time. Also called an instance.
Field
A variable declared inside a class. Every object gets its own copy.

One Flywheel class can produce as many Flywheel objects as the program needs, one for each motor the robot actually has.

3 Creating an object with new

The keyword new builds an object from a class. It goes on the right of the equals sign, followed by the class name and parentheses.

Main.javaJava
class Flywheel {
    int canId;
    String name;
}

public class Main {
    public static void main(String[] args) {
        Flywheel shooter = new Flywheel();
        shooter.canId = 5;
        shooter.name = "Shooter Flywheel";

        System.out.println(shooter.name + " on CAN " + shooter.canId);
    }
}
output
Shooter Flywheel on CAN 5

Line 8 declares a variable named shooter whose type is Flywheel and builds a new object for it to hold. Lines 9 and 10 reach into that object with a dot and set each field. A dot after a variable always means "look inside the object this variable holds."

The class name is not a value

Flywheel on its own names the blueprint. It cannot be printed, assigned, or asked for its canId. Only an object made with new Flywheel() has fields to read.

4 Fields start with default values

A local variable inside a method must be assigned before you can read it. A field is different. The moment new builds the object, every field already holds a default value, even one you never touched.

Main.javaJava
Flywheel shooter = new Flywheel();

System.out.println(shooter.canId);
System.out.println(shooter.name);
output
0
null

An int field defaults to 0. A String field, like every field whose type is not one of the five basic types, defaults to null, meaning it points at no object at all. You met null in the arrays lesson as the default for a String slot. A field follows the same rule.

5 Multiple objects, independent data

Each call to new builds a separate object with its own fields. Changing one object never touches another, even when both come from the same class.

Main.javaJava
Flywheel left = new Flywheel();
left.canId = 3;
left.name = "Left Flywheel";

Flywheel right = new Flywheel();
right.canId = 4;
right.name = "Right Flywheel";

System.out.println(left.name + " uses CAN " + left.canId);
System.out.println(right.name + " uses CAN " + right.canId);
output
Left Flywheel uses CAN 3
Right Flywheel uses CAN 4

left and right are two separate objects. Setting left.canId has no effect on right.canId. A real robot with two flywheel motors needs exactly this, one object per motor, each tracking its own CAN ID and name.

Object and instance mean the same thing

"Create an object" and "create an instance" describe the same action. Both terms show up constantly in Java documentation and in this course from here on.

8 Common mistakes

Watch out for these
  • Forgetting new. Flywheel shooter = Flywheel(); does not compile.
  • Trying to read a field from the class name itself, such as Flywheel.canId, instead of from an object.
  • Assuming a freshly built object has no values at all. Every field already holds its default, 0, false, or null, depending on its type.
  • Mixing up "class" and "object". A class is written once. An object is built, possibly many times, from that one class.
  • Expecting two objects built from the same class to share data. They never do.
Exercise

Drivetrain Motors

Build two objects that represent the two motors on a simple drivetrain.

  1. Write a class Motor with fields canId (int) and name (String).
  2. Create a Motor object named leftDrive on CAN 1 named "Left Drive".
  3. Create a second Motor object named rightDrive on CAN 2 named "Right Drive".
  4. Print a line for each in the form name on CAN canId.
  5. Bonus: create a third Motor, set only its canId, and print it to see the default value of the field you left alone.
Show one possible solution
solution · Main.java
class Motor {
    int canId;
    String name;
}

public class Main {
    public static void main(String[] args) {
        Motor leftDrive = new Motor();
        leftDrive.canId = 1;
        leftDrive.name = "Left Drive";

        Motor rightDrive = new Motor();
        rightDrive.canId = 2;
        rightDrive.name = "Right Drive";

        System.out.println(leftDrive.name + " on CAN " + leftDrive.canId);
        System.out.println(rightDrive.name + " on CAN " + rightDrive.canId);

        Motor climber = new Motor();
        climber.canId = 3;
        System.out.println(climber.name + " on CAN " + climber.canId);
    }
}
output
Left Drive on CAN 1
Right Drive on CAN 2
null on CAN 3

climber.name prints null because it was never assigned. The field existed the moment new Motor() ran. It just held its default value.
