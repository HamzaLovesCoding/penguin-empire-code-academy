Lesson 3

Variables & Data Types

A robot is nothing but numbers that change: speeds, voltages, positions, counts. A variable is a named box you keep one of those numbers in. This lesson is where your programs stop being fixed text and start holding data.

1 Why this matters

Nine out of ten

One season the intake speed 0.65 was typed directly into ten different places in the code. Somebody decided it should be 0.8, went through, changed it, and missed one.

For two meetings the intake ran at full power everywhere except during autonomous, and nobody could work out why auto kept jamming. The fix took two seconds once they found it.

A number typed in ten places is ten chances to be wrong. A number stored in one named box is one place to be right. That box is a variable, and by the end of this page you'll have built the exact fix that would have saved those two meetings.

2 A variable is a labelled box

Think of the bins on the pit cart. Each one has a label written on tape, like ZIP TIES or HEX KEYS, and it has contents. The label stays the same while the contents change.

In code the label is the name, and the contents are the value.

Java also makes you say what kind of thing goes in the box, before you use it. The bin is shaped: the battery bin holds batteries, and you can't drop a wrench in it. In Java that shape is the data type, and you declare it first:

the shape of every declaration
double intakeSpeed = 0.65;
//  ^        ^        ^
// type     name    value

Say it out loud until it's automatic: type, name, equals, value, semicolon.

You will see this exact shape again

In Phase 2 you'll write SparkMax leftMotor = new SparkMax(2, MotorType.kBrushless);, and it is the same four parts in the same order. Type, name, equals, value. Learn the shape once here and that line will look familiar instead of frightening.

3 The five types you need

int
Whole numbers, no decimal point. int teamNumber = 2551; Use it for CAN IDs, game-piece counts, port numbers.
double
Numbers with a decimal point. double motorSpeed = 0.65; Use it for motor output, voltage, distance.
boolean
Exactly true or false, no quotes. boolean hasGamePiece = true; Use it for yes/no questions like "is a limit switch pressed?"
char
A single character in single quotes. char alliance = 'R';
String
Text in double quotes. String robotName = "Penguin One";
Two rules that trip up everybody
  • String is capitalised; the other four are lowercase. That's not a typo and the compiler won't forgive it. (The reason: String is a class and the others are primitives. The full story is in Unit J5.)
  • 'R' is a char. "R" is a String. Single quotes versus double quotes make two different types that don't swap freely.

Here are all five, declared and printed:

Main.java Java 
public class Main {
    public static void main(String[] args) {
        int teamNumber = 2551;              // whole number, no decimal allowed
        double batteryVoltage = 12.6;       // decimal point means double
        boolean isEnabled = false;          // only ever true or false, no quotes
        char allianceColor = 'B';           // SINGLE quotes, exactly one character
        String robotName = "Penguin One";   // DOUBLE quotes, capital S on String

        System.out.println(teamNumber);
        System.out.println(batteryVoltage);
        System.out.println(isEnabled);
        System.out.println(allianceColor);
        System.out.println(robotName);
    }
}
output
2551
12.6
false
B
Penguin One

4 Declare, assign, reassign

Three different moves, and they're easy to confuse:

Declare
int gamePieces; The bin exists, and it's empty.
Initialize
int gamePieces = 0; Make the bin and put something in it. Do this almost always.
Reassign
gamePieces = 3; No type this time. The bin already exists; you're just changing what's inside.

You write the label on the bin once. After that you only change the contents. Writing int gamePieces = 3; a second time is an error, because you can't build the same bin twice.

Main.java Java 
public class Main {
    public static void main(String[] args) {
        int gamePieces = 0;
        System.out.println("Start of match: " + gamePieces);

        gamePieces = 1;                       // no int this time - the box already exists
        System.out.println("Picked one up:  " + gamePieces);

        gamePieces = gamePieces + 1;          // read it as "gamePieces gets gamePieces plus one"
        System.out.println("Picked another: " + gamePieces);
    }
}
output
Start of match: 0
Picked one up:  1
Picked another: 2

5 Why = does not mean “equals”

A lot of later code only makes sense once this clicks. In Java, = means “put the thing on the right into the box on the left.”

Read it out loud as “gets”. So speed = 0.7; is “speed gets 0.7.”

That's why gamePieces = gamePieces + 1; makes perfect sense. As an equation it's nonsense, since nothing equals itself plus one. As an instruction it's obvious: work out the right side first (whatever gamePieces was, plus one), then put that result back in the box.

Right side first, always

Java finishes working out everything to the right of the = before it stores anything. Once you internalise that, half of all “wait, why is it that number?” questions answer themselves.

6 Naming things

Rules the compiler enforces: start with a letter, no spaces, case-sensitive (speed and Speed are two different boxes), and you can't use a Java keyword like class or int.

Rules the team enforces: use camelCase (first word lowercase, later words capitalised, like leftMotorSpeed), and make the name say what's in it.

double x = 0.65; is perfectly legal and completely useless. double intakeSpeed = 0.65; is the same code that a teammate can read at 1 a.m. at competition. A short name saves you a few seconds today and can cost you twenty minutes later.

7 final: the box you nail shut

Put final in front of a declaration and the compiler will refuse to let anyone reassign it, including you, six weeks later, at 1 a.m.

Main.javaJava
final double INTAKE_SPEED = 0.65;

The convention for a final value is SCREAMING_SNAKE_CASE. This is the fix for the nine-out-of-ten bug: one nailed-shut box, referenced everywhere, changed in one place.

This grows up into Constants.java

In Phase 2 this idea becomes a whole file called Constants.java. Port numbers, speeds, and PID setpoints are all final and all in one place, so nobody ever hunts down ten copies of 0.65 again. Remember the word Constants; you'll meet it in Unit 7.

One more thing you've been using without a name: that + inside println. When one side of a + is text, Java turns the other side into text and glues them together. That's string concatenation, and it's how you print a label next to a value. (What + does with two numbers is the next lesson.)

9 What the compiler rejects

These four lines all fail, and the message tells you exactly why. This is real javac output, not a paraphrase:

This does not compile
broken.java
int gamePieces = 2.5;
// error: incompatible types: possible lossy conversion from double to int

double speed = "fast";
// error: incompatible types: String cannot be converted to double

final int MAX_ID = 5;
MAX_ID = 6;
// error: cannot assign a value to final variable MAX_ID

int class = 3;
// error: not a statement / <identifier> expected

Notice the pattern: the compiler names the two types it couldn't reconcile. “String cannot be converted to double” tells you what you gave it and what it wanted. Learning to read that one sentence is most of debugging.

11 Common mistakes

Watch out for these
  • “= means equals.” It means gets. The right side is worked out, then stored in the box on the left. That's why count = count + 1; is normal, not nonsense.
  • “int b = a; links b to a.” It copies the value once. Changing a afterwards never touches b.
  • “String and string are both fine.” Java is case-sensitive and only String exists. string gets you cannot find symbol.
  • “'R' and "R" are the same.” Single quotes make a one-character char; double quotes make a String.
  • “You write the type every time.” Only once, at declaration. After that, just the name.
  • “A shorter name is a better name.” Name the box after what's in it.
Mini-project

The Robot Status Board

Every robot prints a status block to the Driver Station on startup. Build one out of variables, so that changing the robot means editing values at the top instead of hunting through print statements.

  1. Declare five variables: teamNumber (int), robotName (String), batteryVoltage (double), allianceColor (char), isEnabled (boolean).
  2. Print a header line: === ROBOT STATUS ===.
  3. Print one labelled line per variable, using + to join the label to the value.
  4. Bonus: add final int MAX_MOTOR_ID = 12; and print it as Max CAN ID: 12.
Stuck? Reveal one possible solution
solution · Main.java
public class Main {
    public static void main(String[] args) {
        int teamNumber = 2551;
        String robotName = "Penguin One";
        double batteryVoltage = 12.6;
        char allianceColor = 'B';
        boolean isEnabled = false;
        final int MAX_MOTOR_ID = 12;

        System.out.println("=== ROBOT STATUS ===");
        System.out.println("Team:      " + teamNumber);
        System.out.println("Robot:     " + robotName);
        System.out.println("Battery:   " + batteryVoltage + " V");
        System.out.println("Alliance:  " + allianceColor);
        System.out.println("Enabled:   " + isEnabled);
        System.out.println("Max CAN ID: " + MAX_MOTOR_ID);
    }
}
output
=== ROBOT STATUS ===
Team:      2551
Robot:     Penguin One
Battery:   12.6 V
Alliance:  B
Enabled:   false
Max CAN ID: 12

Notice every value lives at the top and every println just refers to it by name. Swap in a different robot by editing six lines, not sixteen.
