1 Why this matters

The 80% rule is arithmetic

The team once pushed a motor at roughly 90% power. It fried so badly it wouldn't run for more than about five seconds.

The rule that came out of it is now team law: keep output under about 0.8, or add another motor instead of pushing one harder.

The motor won't enforce that rule for you, and neither will the compiler. What enforces it is one line of arithmetic:

the whole lesson, in one line
double commanded = Math.min(0.8, Math.max(-0.8, requested));

By the end of this lesson you'll understand every part of that line: how to take a number you have, do something to it, and get a number you can trust.

2 What an expression is

An expression is anything Java can boil down to a single value. 5 is an expression. 2 + 3 is an expression. batteryVoltage / 12.6 * 100 is an expression.

Think of the scale in the pit. You pile parts on it and the display shows one number. You don't get “3 kg plus a bolt.” The pile is the expression; the display is evaluation.

The right-hand side of = is always an expression, and it is always worked out completely before anything is stored.

That's the same “gets” rule from the last lesson, with more happening on the right now.

3 The five arithmetic operators

+
Add. 10 + 4 is 14.
-
Subtract. 10 - 4 is 6.
*
Multiply. It's a star, never x. 10 * 4 is 40.
/
Divide. 10 / 4 is 2. Yes, 2. Section 4 explains why.
%
Remainder, said “modulo”. 10 % 4 is 2.
Main.java Java 
public class Main {
    public static void main(String[] args) {
        int totalTicks = 42;
        int matchSeconds = 15;

        System.out.println("add:      " + (totalTicks + matchSeconds));
        System.out.println("subtract: " + (totalTicks - matchSeconds));
        System.out.println("multiply: " + (totalTicks * matchSeconds));
        System.out.println("divide:   " + (totalTicks / matchSeconds));   // 42/15 is 2.8 - but both are int
        System.out.println("remainder:" + (totalTicks % matchSeconds));   // 15 goes into 42 twice, 12 left
    }
}
output
add:      57
subtract: 27
multiply: 630
divide:   2
remainder:12

Notice every sum is wrapped in ( ). They're there for a reason, and section 7 shows what happens without them.

4 The silent zero

If both sides of / are int, the answer is an int, and Java chops off everything after the decimal point.

It does not round. 7 / 2 is 3. 1 / 2 is 0.

How this bites on a robot

You write double halfSpeed = 1 / 2; meaning “half power.” Java computes 1 / 2 as ints first, which gives 0, and only then widens it into a double. Your variable holds 0.0.

The motor does nothing, nothing crashes, and nothing turns red. The mechanism just sits there while you stare at code that looks correct. This is one of the few Java bugs that produces neither an error nor a warning. You just get a wrong number passed along to everything after it. When a mechanism does nothing at all, check your division.

The fix is to make one side a decimal. Here is the same division five ways:

Main.java Java 
System.out.println(7 / 2);              // both int - fraction chopped
System.out.println(7.0 / 2);            // one decimal promotes the whole thing
System.out.println(7 / 2.0);            // same, on the other side
System.out.println((double) 7 / 2);     // cast FIRST, then divide
System.out.println((double) (7 / 2));   // divide first - damage already done
output
3
3.5
3.5
3.5
3.0

Look at the last two. Same characters, different parentheses, different answer.

5 Modulo: the leftover

47 % 20 is 7: twenty goes into forty-seven twice, with seven left over. It's more useful than it sounds:

  • Split a time. 150 / 60 gives 2 minutes; 150 % 60 gives the leftover 30 seconds.
  • Split encoder ticks into whole rotations plus leftovers.
  • “Is this even?” n % 2 is 0 for every even number. You'll use that in Unit J2.

6 Promotion & casting

When one side of an operation is a double, Java promotes the other side to double and the answer is a double. 3 * 2.0 is 6.0, not 6. That's why printing a double shows 0.8 and 1.0 rather than .8 and 1.

A cast forces a type change on purpose. (int) 12.9 is 12. A cast truncates; it does not round. (double) 7 is 7.0.

A cast tells the compiler you meant to lose something, so only cast when you do.

7 Precedence and the + trap

*, / and % all happen before + and -, exactly like maths class. So 2 + 3 * 4 is 14, not 20.

You don't need to memorise the rest of the precedence table. Experienced programmers just add parentheses whenever the answer isn't obvious at a glance. Two keystrokes save a teammate ten seconds of squinting at midnight.

This next one catches a lot of people. + means “add” when both sides are numbers, and “glue” when either side is text, and Java reads left to right:

Main.java Java 
System.out.println(2 + 3 * 4);            // * runs first
System.out.println((2 + 3) * 4);          // parentheses win
System.out.println("Total: " + 2 + 3);    // text is on the LEFT - both glue on
System.out.println("Total: " + (2 + 3));  // parentheses force the sum first
System.out.println(2 + 3 + " pieces");    // text is on the RIGHT - 2+3 add first
output
14
20
Total: 23
Total: 5
5 pieces
Rule of thumb

Wrap any sum you print in parentheses, every time. It costs nothing and prevents a whole category of confusing output.

8 Shorthand: += and ++

gamePieces = gamePieces + 1; is so common it has a shorthand: gamePieces += 1;. For adding exactly one, there's gamePieces++;.

The whole family is +=, -=, *=, /=, plus ++ and --. Nothing new is happening; this is still “box gets the result of an expression.”

Main.java Java 
int gamePieces = 0;
gamePieces = gamePieces + 1;
System.out.println("after + 1:  " + gamePieces);
gamePieces += 2;
System.out.println("after += 2: " + gamePieces);
gamePieces++;
System.out.println("after ++:   " + gamePieces);
gamePieces--;
System.out.println("after --:   " + gamePieces);

double speed = 0.5;
speed *= 2;
System.out.println("after *= 2: " + speed);   // 1.0, not 1 - speed is a double
output
after + 1:  1
after += 2: 3
after ++:   4
after --:   3
after *= 2: 1.0

9 The Math toolbox

Java ships a class called Math full of ready-made calculations. You use them by writing the class name, a dot, and the name:

Math.abs(-0.93)
Gives 0.93. Use it for “how far is the stick pushed?” when direction doesn't matter.
Math.max(-0.8, x)
The larger of the two. Use it as a floor: never below −0.8.
Math.min(0.8, x)
The smaller of the two. Use it as a ceiling: never above 0.8.
Math.round(12.64)
Gives 13. It rounds properly, unlike (int).
Why Math. and not a variable?

Math.abs(...) is called on the class name Math itself, not on a variable you made. That's a static call, and Unit J5 explains why some things work that way. For now: Math. then the name.

10 Clamping: the 80% rule as code

Put a floor and a ceiling together and you get the line from the top of the page:

Main.java Java 
double requested = 0.95;
double clamped = Math.min(0.8, Math.max(-0.8, requested));
System.out.println("requested: " + requested);
System.out.println("clamped:   " + clamped);

double stick = -0.93;
System.out.println("magnitude: " + Math.abs(stick));
System.out.println("rounded:   " + Math.round(12.64));   // 13 - a cast would give 12
System.out.println("bigger:    " + Math.max(3, 9));
output
requested: 0.95
clamped:   0.8
magnitude: 0.93
rounded:   13
bigger:    9

Read the clamp inside-out. Math.max(-0.8, requested) drags anything below −0.8 up to −0.8. Then Math.min(0.8, ...) drags anything above 0.8 down to 0.8. Whatever comes out is inside the safe band, always.

You will write this line again

In Phase 2 this exact expression goes around the output of a PID controller before it reaches motor.set(...). The controller doesn't know about the team's 80% rule. You do, so you clamp.

13 Common mistakes

Watch out for these
  • “/ always gives the real answer.” Only if at least one side is a double. int / int truncates, silently, every time.
  • “Casting rounds.” (int) chops. Math.round(...) rounds. (int) 0.99 is 0.
  • “+ always adds.” It glues the moment either side is text, and Java works left to right.
  • “% is a percent sign.” It's the remainder operator. Percentages are just / 100, done by hand.
  • “speed += 1 is different from speed = speed + 1.” Identical result; += is just shorter.
  • “If the maths were wrong the compiler would tell me.” The compiler checks grammar, not intent. 1 / 2 is perfect grammar and the wrong number.
  • “I should memorise the whole precedence table.” Learn * / % before + -, then use parentheses for everything else.
Mini-project

The Match Maths Report

Before every match someone converts numbers in their head: how long is the match, how many full rotations is that, is the battery good enough. Make the program do it.

  1. Match length. From int matchSeconds = 150;, print Match length: 2m 30s using / for the minutes and % for the seconds.
  2. Rotations. From int totalTicks = 47; and TICKS_PER_ROTATION = 20, print Rotations: 2 (+7 ticks).
  3. Battery percentage. From 11.4 volts out of 12.6, print it twice, once raw and once through Math.round(...), so the difference is visible.
  4. Bonus: take double requested = 0.95; and print the clamped command.
Stuck? Reveal one possible solution
solution · Main.java
public class Main {
    public static void main(String[] args) {
        int matchSeconds = 150;
        int minutes = matchSeconds / 60;
        int seconds = matchSeconds % 60;
        System.out.println("Match length: " + minutes + "m " + seconds + "s");

        int totalTicks = 47;
        final int TICKS_PER_ROTATION = 20;
        int fullRotations = totalTicks / TICKS_PER_ROTATION;
        int leftover = totalTicks % TICKS_PER_ROTATION;
        System.out.println("Rotations: " + fullRotations + " (+" + leftover + " ticks)");

        double batteryVolts = 11.4;
        final double FULL_VOLTS = 12.6;
        double percent = batteryVolts / FULL_VOLTS * 100;
        System.out.println("Battery: " + percent + "%");
        System.out.println("Battery: " + Math.round(percent) + "%");

        double requested = 0.95;
        double commanded = Math.min(0.8, Math.max(-0.8, requested));
        System.out.println("Commanded: " + commanded);
    }
}
output
Match length: 2m 30s
Rotations: 2 (+7 ticks)
Battery: 90.47619047619048%
Battery: 90%
Commanded: 0.8

Look at that raw percentage: 90.47619047619048. That isn't a bug. It's what a double actually holds. Nobody wants to read it on a dashboard, which is why the second line exists. Deciding how much precision a human needs is part of the job.
