Methods That Act on Objects

A method written without static belongs to an object rather than to the class. It reads and changes that one object's own fields.

1 A method without static

Every method so far has been static, sitting next to main and called by name alone. Leave static off, and the method belongs to an object instead of to the class. This is called an instance method.

the shape
class Flywheel {
    double currentRPM;
    double targetRPM;

    void spinUp() {
        currentRPM = targetRPM;
    }
}

Inside spinUp(), the plain names currentRPM and targetRPM refer to the fields of whichever Flywheel object the method is running on. There is no need to write this. here, since nothing else in the method shares those names.

2 Calling it with a dot

An instance method is called through an object, the same dot you already use to reach a field.

Main.javaJava
class Flywheel {
    int canId;
    String name;
    double targetRPM;
    double currentRPM;

    Flywheel(int canId, String name, double targetRPM) {
        this.canId = canId;
        this.name = name;
        this.targetRPM = targetRPM;
        this.currentRPM = 0;
    }

    void spinUp() {
        currentRPM = targetRPM;
    }
}

public class Main {
    public static void main(String[] args) {
        Flywheel shooter = new Flywheel(5, "Shooter Flywheel", 5000);
        System.out.println(shooter.currentRPM);

        shooter.spinUp();
        System.out.println(shooter.currentRPM);
    }
}
output
0.0
5000.0

shooter.spinUp() runs the method with currentRPM and targetRPM pointing at shooter's own fields. A second Flywheel object would keep its own currentRPM completely untouched.

No object, no call

An instance method cannot be called by name alone the way a static method can. spinUp(); on its own, with no object and no dot, fails to compile with cannot find symbol. Java has no idea which Flywheel you mean.

3 A method that changes fields

spinUp() is a void method whose entire job is changing state. A second method can undo it the same way.

Main.javaJava
void stop() {
    currentRPM = 0;
}

Nothing is passed in and nothing is returned. Calling shooter.stop() is only useful for the change it makes to shooter's own currentRPM.

4 A method that returns a value

An instance method can return a value the same way any method can, computed from the object's own fields.

Main.javaJava
boolean isAtSpeed() {
    return Math.abs(currentRPM - targetRPM) <= 50;
}
Main.java
Flywheel shooter = new Flywheel(5, "Shooter Flywheel", 5000);
System.out.println(shooter.isAtSpeed());

shooter.spinUp();
System.out.println(shooter.isAtSpeed());

shooter.stop();
System.out.println(shooter.isAtSpeed());
output
false
true
false

isAtSpeed() reads currentRPM and targetRPM but changes neither. The same object gives a different answer at different points in the program, because its own currentRPM changed in between.

5 One method calling another

A method belonging to an object can call another method on that same object, no dot needed, the same way it can read a field directly.

Main.javaJava
void report() {
    System.out.println(name + ": " + currentRPM + " / " + targetRPM
        + " RPM, at speed: " + isAtSpeed());
}
output
Shooter Flywheel: 0.0 / 5000.0 RPM, at speed: false
Shooter Flywheel: 5000.0 / 5000.0 RPM, at speed: true
Shooter Flywheel: 0.0 / 5000.0 RPM, at speed: false

report() calls isAtSpeed() exactly like a static method calls another static method. The difference is that both methods run against the one object that report() was called on.

This is the shape of a WPILib subsystem

A real robot subsystem is a class exactly like this one, fields for its current state, a constructor, and methods that read or change that state. Phase 2 opens with a class built this way.

8 Common mistakes

Watch out for these
  • Calling spinUp(); with no object and no dot, which gives cannot find symbol.
  • Leaving off the parentheses, shooter.spinUp; instead of shooter.spinUp();, which gives not a statement.
  • Forgetting a return type or a return statement on a method meant to answer a question, such as isAtSpeed().
  • Expecting one object's method call to affect a different object of the same class.
  • Calling report() expecting it to change currentRPM. It only reads the fields and prints them.
Exercise

Intake Rollers

Build a small class whose methods change and report its own state.

  1. Write class Intake with fields canId, name, and rollersOn (a boolean).
  2. Give it a constructor that takes canId and name, and starts rollersOn at false.
  3. Write instance methods start() and stopRollers() that set rollersOn to true and false.
  4. Write report() to print the name and whether the rollers are on.
  5. Bonus: write isRunning() that returns rollersOn, and call it from inside report() instead of reading the field directly.
Show one possible solution
solution · Main.java
class Intake {
    int canId;
    String name;
    boolean rollersOn;

    Intake(int canId, String name) {
        this.canId = canId;
        this.name = name;
        this.rollersOn = false;
    }

    void start() {
        rollersOn = true;
    }

    void stopRollers() {
        rollersOn = false;
    }

    boolean isRunning() {
        return rollersOn;
    }

    void report() {
        System.out.println(name + " rollers on: " + isRunning());
    }
}

public class Main {
    public static void main(String[] args) {
        Intake intake = new Intake(7, "Intake");

        intake.report();
        intake.start();
        intake.report();
        intake.stopRollers();
        intake.report();
    }
}
output
Intake rollers on: false
Intake rollers on: true
Intake rollers on: false

report() never changes rollersOn itself. It calls isRunning(), which only reads it, so calling report() as many times as you like never changes what it prints.
