static vs. Instance

An instance field belongs to one object. A static field belongs to the class itself, a single copy shared by every object made from it.

1 Two kinds of fields

Every field you have written so far is an instance field. Each object gets its own separate copy, exactly like canId and name in the last three lessons. Adding static to a field changes that completely. A static field has exactly one copy, owned by the class, and every object made from that class shares it.

Main.javaJava
class Flywheel {
    static int flywheelCount = 0;

    int canId;
    String name;

    Flywheel(int canId, String name) {
        this.canId = canId;
        this.name = name;
        flywheelCount = flywheelCount + 1;
    }
}

public class Main {
    public static void main(String[] args) {
        Flywheel shooter = new Flywheel(5, "Shooter Flywheel");
        Flywheel climber = new Flywheel(6, "Climber Flywheel");
        Flywheel spare = new Flywheel(7, "Spare Flywheel");

        System.out.println(Flywheel.flywheelCount);
    }
}
output
3

Three objects were built. Each one has its own canId, but there is only one flywheelCount in the whole program. Every constructor call adds to the same number.

2 Reached through the class name

Flywheel.flywheelCount reads the static field through the class name, not through any one object. That matches what the field actually is, a single value that belongs to Flywheel as a whole rather than to shooter or climber specifically.

Instance field
One copy per object. Reached with object.field.
Static field
One copy per class. Reached with ClassName.field.

3 Static methods cannot see instance fields

Every method you wrote before lesson 22, and main itself, is static. A static method runs without any particular object behind it, so it has no way to reach an instance field. There is no object to ask.

Main.javaJava
class Flywheel {
    double currentRPM;

    static void badStaticMethod() {
        System.out.println(currentRPM);
    }
}
output
error: non-static variable currentRPM cannot be referenced from a static context

This is the same error methods.html mentioned in the other direction. main is static, so it cannot call an instance method without an object either. A static method can only touch static fields and other static methods directly.

4 A static constant shared by every object

A value that describes a rule for the whole class, not one object's own data, is a natural fit for static final. Every Flywheel should respect the same maximum speed, so the limit is written once.

Main.javaJava
class Flywheel {
    static final double MAX_RPM = 6000;

    int canId;
    String name;
    double targetRPM;

    Flywheel(int canId, String name, double targetRPM) {
        this.canId = canId;
        this.name = name;
        this.targetRPM = Math.min(targetRPM, MAX_RPM);
    }
}

public class Main {
    public static void main(String[] args) {
        Flywheel shooter = new Flywheel(5, "Shooter Flywheel", 5200);
        Flywheel overdriven = new Flywheel(6, "Overdriven Flywheel", 9000);

        System.out.println(shooter.targetRPM);
        System.out.println(overdriven.targetRPM);
    }
}
output
5200.0
6000.0

MAX_RPM is static because every Flywheel shares the same limit, and final because that limit never changes once the program starts, the same reason final showed up for ordinary constants back in lesson 3. overdriven asked for 9000 and was clamped down to the shared limit in the constructor.

5 Which one to use

Two short rules cover almost every case.

  1. Data that differs per object is an instance field. canId, currentRPM, and targetRPM all vary from one Flywheel to the next.
  2. Data or behavior that belongs to the whole class is static. A count of how many objects exist, a shared limit, or a helper like Math.max that needs no object's state at all.
Math is a static-only class

Math.max(3, 9) never creates a Math object. Every method on Math is static, because none of them need an object's own state to do their job.

8 Common mistakes

Watch out for these
  • Reading or changing an instance field directly from a static method, which gives non-static variable cannot be referenced from a static context.
  • Making a value that should be shared, like a counter or a shared limit, an ordinary instance field. Each object then keeps its own separate copy instead of one shared value.
  • Reaching a static field through an object, such as shooter.flywheelCount. It compiles, but the class name makes clear the value does not belong to shooter alone.
  • Forgetting that a static field keeps its value for the entire run of the program, across every object ever built.
Exercise

Counting the Fleet

Add class-wide data to the Motor class from earlier lessons.

  1. Add a static field motorCount, starting at 0, and increase it by one inside the constructor.
  2. Add a static final constant MAX_CAN_ID set to 20.
  3. In the constructor, set canId to whichever is smaller, the value passed in or MAX_CAN_ID.
  4. Create three Motor objects, one with a canId above 20, and print each one's canId.
  5. Bonus: write a static method describeFleet() that prints "Fleet size: " + motorCount + " motors", and call it through the class name.
Show one possible solution
solution · Main.java
class Motor {
    static int motorCount = 0;
    static final int MAX_CAN_ID = 20;

    int canId;
    String name;

    Motor(int canId, String name) {
        this.canId = Math.min(canId, MAX_CAN_ID);
        this.name = name;
        motorCount = motorCount + 1;
    }

    static void describeFleet() {
        System.out.println("Fleet size: " + motorCount + " motors");
    }
}

public class Main {
    public static void main(String[] args) {
        Motor leftDrive = new Motor(1, "Left Drive");
        Motor rightDrive = new Motor(2, "Right Drive");
        Motor overLimit = new Motor(25, "Over Limit Motor");

        System.out.println(leftDrive.name + " CAN " + leftDrive.canId);
        System.out.println(rightDrive.name + " CAN " + rightDrive.canId);
        System.out.println(overLimit.name + " CAN " + overLimit.canId);

        Motor.describeFleet();
    }
}
output
Left Drive CAN 1
Right Drive CAN 2
Over Limit Motor CAN 20
Fleet size: 3 motors

overLimit asked for CAN 25 and was clamped to 20 by the shared constant. motorCount reached 3 no matter which object you ask, because there is only one copy of it.
