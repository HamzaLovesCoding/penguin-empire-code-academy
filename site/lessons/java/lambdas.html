Lambdas & Functional Interfaces

A lambda is a short way to supply a method without writing a class. This is the last piece of Java you need, and it is the first thing you will write in Phase 2.

1 Too much code for one line

Here is an interface with a single method, and the full ceremony needed to supply one line of behaviour.

Main.javaJava
interface Action {
    void run();
}

Action longWay = new Action() {
    @Override
    public void run() {
        System.out.println("all motors stopped");
    }
};
longWay.run();
output
all motors stopped

Six lines to say one thing. Everything except the println is fixed by the interface, so Java can work it out.

2 The lambda

Write the parameters, an arrow, and the body.

Main.javaJava
Action stopAll = () -> System.out.println("all motors stopped");
stopAll.run();

Same output, one line. The empty () is the parameter list, because run takes none. The arrow separates the parameters from the body.

() -> body
No parameters.
(x) -> body
One parameter. The type is worked out from the interface, so you do not write it.
(a, b) -> body
Two parameters.
() -> { ... }
Use braces when the body needs more than one statement.

3 Functional interfaces

A lambda can only be used where an interface has exactly one method that needs implementing. Such an interface is called a functional interface.

The reason is that Java has to know which method the lambda is. With two methods there would be no way to tell.

A lambda is still an object

Nothing new was added to the language's model. The lambda produces an object that implements the interface, exactly like the six line version did. It is shorter to write, not different in kind.

4 Passing behaviour to a method

Because a lambda is a value, a method can take one as a parameter. That lets you pass behaviour rather than data.

Main.javaJava
static void runTwice(Action a) {
    a.run();
    a.run();
}

runTwice(() -> System.out.println("pulse"));
output
pulse
pulse

runTwice has no idea what it is running. It was handed something to do and did it twice. That is the idea Phase 2 is built on.

5 Method references

When the lambda body is only a call to an existing method, there is a shorter form using two colons.

Main.javaJava
Action a = () -> intake.stop();   // lambda
Action b = intake::stop;          // method reference, same thing

Both produce the same object. Use whichever reads better. The lambda form is clearer when you are learning, and you will see both in real code.

6 The shape Phase 2 opens with

In Phase 2 you bind a controller button to an action. The line looks like this.

RobotContainer.javaJava
controller.triangle().onTrue(
    new InstantCommand(() -> intakeSub.runRoller(0.7))
);

Read it in pieces, all of which you now know. controller.triangle() is a method call that returns an object. .onTrue(...) is a method on that object. Its argument is a new InstantCommand(...), an object being constructed. And the thing passed to that constructor is a lambda saying what to do when the button is pressed.

It is one method call holding an object holding a lambda. Nothing in that line is new to you after this lesson.

9 Common mistakes

Watch out for these
  • Leaving out the empty () when the method takes no parameters.
  • Writing parameter types inside the lambda. Java works them out from the interface.
  • Using a lambda for an interface with more than one method.
  • Forgetting the braces when the body needs several statements.
  • Expecting the body to run at the moment the lambda is written. It runs when something calls it.
Exercise

Button Bindings

Build a tiny version of the Phase 2 binding system.

  1. Write an Action interface with one method.
  2. Write an Intake class with runRoller(double) and stop().
  3. Write a Button class with a name and an onPress(Action) method that stores the action, plus a press() method that runs it.
  4. Bind two buttons using lambdas, then press each one.
  5. Bonus: bind a third using a method reference.
Show one possible solution
solution · Main.java
interface Action { void run(); }

class Intake {
    public void runRoller(double speed) { System.out.println("rollers at " + speed); }
    public void stop() { System.out.println("rollers stopped"); }
}

class Button {
    private final String name;
    private Action action;

    public Button(String name) { this.name = name; }

    public void onPress(Action action) { this.action = action; }

    public void press() {
        System.out.println("[" + name + " pressed]");
        if (action != null) {
            action.run();
        }
    }
}

public class Main {
    public static void main(String[] args) {
        Intake intake = new Intake();

        Button triangle = new Button("triangle");
        Button cross = new Button("cross");
        Button circle = new Button("circle");

        triangle.onPress(() -> intake.runRoller(0.7));
        cross.onPress(() -> intake.runRoller(-0.5));
        circle.onPress(intake::stop);

        triangle.press();
        cross.press();
        circle.press();
    }
}
output
[triangle pressed]
rollers at 0.7
[cross pressed]
rollers at -0.5
[circle pressed]
rollers stopped

The Button class knows nothing about intakes. It stores something to do and runs it on press. Swap the lambdas and the buttons do something else entirely, with no change to Button. That is exactly how RobotContainer works in Phase 2.
