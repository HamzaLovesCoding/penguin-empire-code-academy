Lesson 5

Working with Text (Strings)

On game day the console is your only window into a robot forty feet away that you're not allowed to touch, and it can only show you text you decided to print. What you print is how you find out what the robot is doing.

1 Why this matters

Watch the console

During a match, the programmer's job is not to coach the driver; that's the drive coach's job. Your job is to sit behind the Driver Station and watch the console: the scrolling text window where everything the robot prints shows up.

When something goes wrong, that window is your entire view into a robot you cannot reach.

The console can only ever show you text you decided to print. Write System.out.println(position); and you get:

console
0.42

Which of the nine numbers on this robot is that? Is 0.42 good or bad? The team already learned this on dashboards, where the naming rule became arm/position, not value1. Same rule here.

2 Text that can do things

You've been using String as a box that holds text. A String also comes with a set of skills. You ask it to use one with a dot.

the shape
String subsystem = "IntakeSubsystem";
System.out.println(subsystem.length());   // 15
//                 ^         ^      ^
//              the value   skill   parentheses mean "do it"

Think of the pit crew. You don't reach into someone's toolbox and rummage. You say “Sam, torque wrench,” and Sam does it. subsystem.length() is you asking the string “how long are you?” and it answering.

Asking a value to do something is called calling a method. You've been doing it since lesson 2: System.out.println(...) is a method call. Unit J3 teaches you to write your own; Unit J5 explains how a value comes to have skills at all. Right now you only need the shape: dot, name, parentheses.

Parentheses are not optional

Java won't guess what you meant by subsystem.length. It refuses to compile. Even when a method needs no information, you still write the empty (). The parentheses are what say “do it.”

3 Counting starts at zero

The first character of a String is at position 0.

"Penguin" has 7 characters, at positions 0 through 6. There is no position 7.

the ruler
            length() = 7
   +---+---+---+---+---+---+---+
   | P | e | n | g | u | i | n |
   +---+---+---+---+---+---+---+
     0   1   2   3   4   5   6      <-- position 7 does not exist

So charAt(0) gives 'P', and the last character is at length() - 1. Memorise that expression. You'll write it constantly.

This matters right now: charAt(7) on a 7-character string doesn't print an empty line. It crashes the program. You'll trigger that on purpose in a minute.

4 Reading and slicing

.length()
15, how many characters.
.charAt(0)
'I', the character at one position.
.substring(0, 6)
"Intake", a slice from 0, up to but not including 6.
.substring(6)
"Subsystem", a slice from 6 to the end.
.indexOf("Sub")
6, where it starts, counting from 0.
.contains("take")
true, if it's in there at all. This one gives back a boolean.
Everyone gets substring wrong once

The first number is included; the second is not. substring(0, 6) gives you exactly 6 characters: positions 0, 1, 2, 3, 4, 5. That means the number of characters you get is always end - start.

Main.java Java 
String subsystem = "IntakeSubsystem";

System.out.println(subsystem.length());          // 15 chars, so positions 0 to 14
System.out.println(subsystem.charAt(0));         // position 0 is the FIRST character
System.out.println(subsystem.substring(0, 6));   // 0 up to but not including 6
System.out.println(subsystem.toUpperCase());
System.out.println(subsystem.toLowerCase());
System.out.println(subsystem.indexOf("Sub"));    // Sub starts at 6
System.out.println(subsystem.contains("take"));  // a boolean, not text
output
15
I
Intake
INTAKESUBSYSTEM
intakesubsystem
6
true

5 Cleaning up

.trim()
" Intake " becomes "Intake". It strips spaces off both ends.
.toUpperCase()
"Intake" becomes "INTAKE".
.toLowerCase()
"Intake" becomes "intake".

trim() matters more than it looks. Text that comes from a file, a dashboard field, or a person's typing very often has invisible spaces on the end, and those spaces make two labels that look identical fail to match.

Main.java Java 
String typed = "  Intake  ";
System.out.println("[" + typed + "]");          // brackets make the spaces visible
System.out.println("[" + typed.trim() + "]");
output
[  Intake  ]
[Intake]

Those square brackets are a real debugging trick. Wrap a suspicious string in [ and ] and stray whitespace becomes visible instantly.

6 Strings never change

This catches almost everyone the first time.

Main.java Java 
String name = "Intake";
name.toUpperCase();          // THIS LINE DOES NOTHING
System.out.println(name);    // prints Intake

String shouted = name.toUpperCase();   // catch the result
System.out.println(shouted);           // INTAKE
System.out.println(name);              // still Intake - it was never modified
output
Intake
INTAKE
Intake

Strings in Java are immutable: a String's contents can never be edited after it's created. toUpperCase() doesn't modify name; it hands you back a brand-new String and leaves the original alone. If you don't catch the new one, it evaporates.

Think of the laminator in the pit. You feed in a sheet and get a laminated sheet back. The original sheet is still sitting there, un-laminated. Walk away without picking up the new one and you have nothing.

The line that does nothing

Any line that is just something.someTextMethod(); on its own, with no = in front of it, almost certainly does nothing at all. Text methods return a result. You have to store it or print it.

7 Chaining

Because trim() hands back a String, and a String has skills, you can keep going on the same line:

Main.javaJava
String clean = subsystem.trim().toUpperCase();

Read it strictly left to right: take subsystem, trim it, and whatever that gives you, uppercase that. Each dot operates on whatever the thing to its left produced. This is method chaining, and you'll see it constantly in Phase 2.

8 Comparing text

Two pieces of text are the same when they contain the same characters in the same order, including case.

Main.java Java 
String a = "Intake";
String b = "intake";

System.out.println(a.equals(b));             // false - capital I vs lowercase i
System.out.println(a.equalsIgnoreCase(b));   // true
System.out.println(a.equals("Intake"));      // true

.equals(...) gives back a boolean (true or false), the type you met in the variables lesson.

Don't use == for text yet

Java also has a comparison symbol made of two equals signs. For numbers it does exactly what you'd expect. For text it does something subtly different that catches people out for years. The booleans lesson, two lessons from now, takes it apart properly. Until then the rule is simple and safe: compare text with .equals(...).

9 Escape sequences

A " ends a String, so how do you print one? You escape it with a backslash.

\n
A new line, mid-string.
\t
A tab, for lining up columns.
\"
A literal double quote.
\\
A literal backslash.
Main.java Java 
System.out.println("Line one\nLine two");                  // one println, two lines
System.out.println("Arm\tPosition\tVelocity");             // columns that line up
System.out.println("She said \"CAN ID 16 timed out\"");
System.out.println("Backslash: \\");
output
Line one
Line two
Arm	Position	Velocity
She said "CAN ID 16 timed out"
Backslash: \

Without those backslashes on the third line, the String would end at the second quote and the compiler would be very confused.

10 printf: numbers that don't embarrass you

Remember the battery percentage from the last lesson, 90.47619047619048%? That's what a double really holds, and nobody wants to read it at 90 seconds into a match.

System.out.printf(...) prints a template with slots:

%s
Drop a String (or anything) in here.
%d
Drop a whole number in here.
%.2f
Drop a decimal here, rounded to 2 places.
%%
A literal percent sign.
%n
End the line.
Main.java Java 
double percent = 11.4 / 12.6 * 100;
System.out.println("Battery: " + percent + "%");      // honest, and unreadable
System.out.printf("Battery: %.1f%%%n", percent);      // one decimal place
System.out.printf("%s at %.2f (CAN %d)%n", "Intake", 0.7, 2);
output
Battery: 90.47619047619048%
Battery: 90.5%
Intake at 0.70 (CAN 2)

You don't need to memorise that table. You need to know it exists, so that when a console line looks awful you know there's a fix.

Exception in thread "main" java.lang.StringIndexOutOfBoundsException:

Nothing is broken and you did nothing stupid. The string has 7 characters at positions 0 to 6, and you asked for a position that doesn't exist. The next lesson is entirely about reading exactly this message.

13 Common mistakes

Watch out for these
  • “toUpperCase() changes the string.” Strings are immutable. Every text method hands back a new string; the original is untouched, so you must store what you get.
  • “The first character is at position 1.” It's at 0, and the last is at length() - 1. This is true for arrays too, which is why it's worth burning in now.
  • “substring(0, 6) gives me 7 characters.” The end index is excluded, so you get exactly 6 - 0 = 6.
  • “length and length() are the same.” For a String it's the method length(), with parentheses. Arrays use length with no parentheses. It's an annoying inconsistency, and you'll meet it in Unit J4.
  • “Two strings that look the same must match.” A trailing space or one capital letter is enough. Print them inside brackets to see what's really there.
  • “I should memorise every String method.” Know that length, charAt, substring, trim, contains, indexOf and equals exist. Look up the rest when you need them.
Mini-project

The Match Console Header

At the start of a match the robot should print a header block a person can read at a glance while looking away from the screen. Build it.

  1. Clean the label. Make a String clean that holds ARM, using trim() and toUpperCase() chained on one line.
  2. Print the header: === CONSOLE ===, then ARM (CAN 3).
  3. Print the position with printf to two decimal places, and the atSetpoint flag.
  4. Bonus: print the label's length, its first character, and whether it equalsIgnoreCase("arm").
Stuck? Reveal one possible solution
solution · Main.java
public class Main {
    public static void main(String[] args) {
        String subsystem = "  arm  ";
        int canId = 3;
        double position = 8.9732;
        boolean atSetpoint = true;

        String clean = subsystem.trim().toUpperCase();

        System.out.println("=== CONSOLE ===");
        System.out.println(clean + " (CAN " + canId + ")");
        System.out.printf("  position   %.2f%n", position);
        System.out.println("  atSetpoint " + atSetpoint);
        System.out.println("  label len  " + clean.length());
        System.out.println("  first char " + clean.charAt(0));
        System.out.println("  is arm?    " + clean.equalsIgnoreCase("arm"));
    }
}
output
=== CONSOLE ===
ARM (CAN 3)
  position   8.97
  atSetpoint true
  label len  3
  first char A
  is arm?    true

Compare that to 0.42 on its own. It's the same information, but you can read this version from four feet away while the match is running.
