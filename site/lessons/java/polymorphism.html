Abstraction & Polymorphism

Polymorphism means writing code that works with a parent type and letting each child decide how to respond. It is what lets one loop stop every subsystem on the robot.

25 min Intermediate

1 A child fits where the parent fits

A Flywheel is a Subsystem. So anywhere the code expects a Subsystem, a Flywheel is accepted.

Main.javaJava
Flywheel shooter = new Flywheel("Shooter", 5, 4000);
Intake intake = new Intake("Intake", 2);

Subsystem[] all = { shooter, intake };

for (Subsystem s : all) {
    System.out.println(s.report());
    s.stop();
}
output
Shooter on CAN 5, target 4000.0 RPM
Shooter stopped
Intake on CAN 2
Intake rollers halted

The array holds two different classes. The loop knows nothing about either of them, only that both are subsystems. Adding a third kind of subsystem needs no change to this loop at all.

2 Which version runs

The variable is declared Subsystem, but s.stop() printed Intake rollers halted for the second item. Java picks the method based on what the object really is, not what the variable is declared as.

Declared type against actual type

The declared type decides which methods you are allowed to call. The actual object decides which version runs. A Subsystem variable cannot call spinUp(), because not every subsystem has one, even when the object really is a Flywheel.

3 abstract classes

Sometimes the parent is not a real thing on its own. There is no such object as a plain mechanism. Mark the class abstract and Java refuses to let anyone create one.

Main.javaJava
abstract class Mechanism {
    protected String name;
    public Mechanism(String name) { this.name = name; }
}

Mechanism m = new Mechanism("thing");   // does not compile
error
Main.java:6: error: Mechanism is abstract; cannot be instantiated

An abstract class still has constructors, fields and normal methods. Children use them exactly as before. It simply cannot be created directly.

4 abstract methods

An abstract method has no body. It is a requirement placed on every child.

Main.javaJava
abstract class Mechanism {
    protected String name;
    public Mechanism(String name) { this.name = name; }

    public abstract double outputFor(double input);

    public void describe() {
        System.out.println(name + " at 0.5 gives " + outputFor(0.5));
    }
}

class Roller extends Mechanism {
    public Roller() { super("Roller"); }
    @Override public double outputFor(double input) { return input; }
}

class Geared extends Mechanism {
    public Geared() { super("Geared arm"); }
    @Override public double outputFor(double input) { return input / 4; }
}
output
Roller at 0.5 gives 0.5
Geared arm at 0.5 gives 0.125

Look at describe(). It calls outputFor without knowing what any child does. The parent wrote the shared behaviour and left one hole for each child to fill.

A child that does not supply outputFor will not compile. That is the point. The requirement is enforced rather than remembered.

5 You have already used this

System.out.println accepts an int, a double, a String and objects you write yourself. Overloading explains part of that. The rest is polymorphism, because every class in Java ultimately descends from one parent type.

In Phase 2 this is how the robot works. The scheduler holds a list of commands, calls execute() on each one, and has no idea what any of them do.

8 Common mistakes

Watch out for these
  • Trying to create an object of an abstract class.
  • Extending an abstract class without supplying every abstract method.
  • Calling a child only method through a parent type variable.
  • Giving an abstract method a body. It ends with a semicolon and no braces.
  • Expecting the declared type to decide which version runs. The object decides.
Exercise

Stop Everything

Write one loop that shuts down a whole robot.

  1. Write an abstract Subsystem with a name, a normal report(), and an abstract stop().
  2. Write three children that each stop differently.
  3. Put all three in a Subsystem[] and loop over it calling report() then stop().
  4. Bonus: add a fourth child and confirm the loop needs no edit.
Show one possible solution
solution · Main.java
abstract class Subsystem {
    protected String name;
    public Subsystem(String name) { this.name = name; }

    public abstract void stop();

    public String report() { return name + " reporting"; }
}

class Intake extends Subsystem {
    public Intake() { super("Intake"); }
    @Override public void stop() { System.out.println("Intake rollers halted"); }
}

class Flywheel extends Subsystem {
    public Flywheel() { super("Flywheel"); }
    @Override public void stop() { System.out.println("Flywheel coasting down"); }
}

class Climber extends Subsystem {
    public Climber() { super("Climber"); }
    @Override public void stop() { System.out.println("Climber locked in place"); }
}

public class Main {
    public static void main(String[] args) {
        Subsystem[] all = { new Intake(), new Flywheel(), new Climber() };

        for (Subsystem s : all) {
            System.out.println(s.report());
            s.stop();
        }
    }
}
output
Intake reporting
Intake rollers halted
Flywheel reporting
Flywheel coasting down
Climber reporting
Climber locked in place

Every class stops differently and the loop contains no if at all. Adding a fourth subsystem means writing one class and adding it to the array.
